# 索引优化复测报告

日期：2026-10-26。

本轮针对 [首次实机测试](20261026-索引与遍历实机测试.md) 确认的四项问题实施优化，并再次启动桌面程序验证。完整测量数据见 [复测数据](20261026-索引优化复测数据.json)。

## 实现变化

1. **空闲页面同步。** 根任务完成后发送 `x-file-library-updated` 原生事件，页面重新读取当前列表和标签计数；页面卸载时解除订阅，不增加空闲高频轮询。
2. **无变化不写大快照。** 未发现文件更新、删除或恢复数据时，保留目录快照、活动文件快照和索引状态快照的文件版本。运行状态仍按任务进度更新。
3. **复用索引状态。** 桌面根队列在后台线程串行执行任务，保留独立 CLI 入口。目录与索引状态缓存按文件版本失效；提交后把变化记录应用到缓存，避免下一轮重新解析完整活动状态。索引和导出共用目录快照类型与缓存，持久化使用紧凑 JSON。
4. **缩小扫描范围。** 增加多目标 `targetPaths`，保留不重叠的文件或目录范围；不再把不同目录下的变更合并为公共根目录。服务端待执行任务也保留多目标。目录优先级提示只调整任务范围内的目录。
5. **缩小搜索写入范围。** 每个词项前缀按文档标识分成 16 片。桶内保持 `search-bucket-v2`，manifest 保持 `search-v2` 并增加 `partition_count`。读取器按 manifest 中的路径读取，兼容旧桶；旧搜索布局在下一次有变化的导出时迁移。
6. **快速消费文件通知。** 监听回调通过通道收集路径，按固定 150ms 窗口合并提交；处理文件系统要求重扫的通知，包括无路径的通知。

删除了原来的桌面子进程调度方法、公共路径扩大逻辑、重复目录快照类型、重复全量合并方法及旧搜索桶手工逐字段写入实现。运行日志只记录写出数量，不再复制并输出整份导出路径数组。

## 测量口径

- 与基线相同的 Apple M4、16 GiB 内存、macOS，Rust debug 构建和 Vite 前端。
- 初始资料库为 10,000 个短 Markdown 文件、100 个目录，正文合计 13,598,890 字节；测试配置和资料库独立。
- 桌面计时为后台线程内真实任务的耗时，不含监听合并窗口、界面渲染和辅助功能工具开销。基线使用独立 worker 子进程，包含子进程启动；本轮取消该进程边界正是优化内容之一。
- CLI 仍为每轮启动独立进程，另列结果，不能把其耗时等同于桌面热缓存任务。
- 操作系统文件缓存、其他进程负载和温度未受控，基线没有在本轮重新运行。下列前后差值是本机样本，不是发布版性能承诺或严格统计结论。
- 索引阶段包含历史状态、遍历、属性比较、摘要和持久化，不是纯 `readdir` 耗时。

## 桌面任务复测

| 场景 | 基线 | 本轮 | 扫描范围与结果 |
| --- | ---: | ---: | --- |
| 首次完整建库 | 9,707ms | 9,316ms | 两轮均扫描、索引 10,000 个文件 |
| 无变化全库刷新 | 549 / 587ms | 266 / 254ms | 扫描 10,000，索引 0，导出重写 0 |
| 单文件追加，摘要词项不变 | 811ms | 592ms | 扫描 1，索引 1，导出重写 4 |
| 单文件修改，搜索词项改变 | 2,049ms | 640ms | 扫描 1，索引 1，导出重写 18 |
| 跨 100 个目录修改 100 个文件 | 5,449ms，两次任务 | 2,918ms，一次任务 | 扫描从 1 + 10,000 降为 100 |
| 修改 1,000 个文件，运行中再次修改首个文件 | 5,628ms | 4,039ms | 本轮扫描 1,000 + 1，全部更新与最终再次修改均正确 |

两个普通单文件保存场景各只产生一次任务；千文件场景的第二次任务处理真实的运行中再次修改。文件系统仍可能产生后续通知，不能据此承诺任意平台和保存方式永远只调度一次。

单文件追加的索引阶段从 524ms 降到 358ms；词项改变从 561ms 降到 315ms。首次完整导出仍需创建大量文件，本轮没有明显消除首次建库成本。

搜索分片使初次导出文件数从 10,126 增至 10,366。分片用更多小文件换取较小的增量处理范围，并非单纯减少所有场景的文件数。

## 空闲页面的实际验证

在目录页面保持空闲，通过文件系统新增 `ZZ-LIVE-SENTINEL.md`：

- 没有点击刷新或切换目录，新增文档自动出现在列表中。
- 时间和类型标签计数均从 10,000 更新到 10,001。
- 删除该文档后，列表自动移除文档，计数恢复 10,000。
- 最终构建重启后重复新增、删除，同样通过。

持续写入期间还实际切换了目录。操作发起时间处于后台任务执行区间内，操作与辅助功能树采集合计 533ms，能够显示目标内容。此值包含自动化工具开销，不能作为帧时间、原生 API 延迟或 P95 指标。

## 快照写入审计

两次桌面无变化刷新，对整个 `.ai-index` 的文件 inode、修改时间和大小进行前后比对，均只有 `runtime-status.json` 发生变化：

- `runtime/export-catalog-snapshot.json` 保持原版本。
- `runtime/active-file-state-snapshot.json` 保持原版本。
- `runtime/index-state.json` 保持原版本。
- 正式导出文件保持原版本。

独立 CLI 连续三次无变化刷新，新增的 `rewrittenSnapshots` 指标也全部为空，避免只统计导出而漏掉运行快照。

**发生文档变化时，目录和活动文件快照仍会整份序列化。** 本轮消除了无变化的大快照写入及多处重复读取，并没有让全部持久化成本都变成 O(变化量)。这是单文件索引阶段仍有约 315–358ms 成本的原因之一。

## 持续写入与正确性

每隔约 2 秒更新 1,000 个文件，共 30 批：

| 指标 | 基线 | 本轮 |
| --- | ---: | ---: |
| 串行任务数 | 21 | 24 |
| 累计扫描文件数 | 200,021 | 24,000 |
| 单轮最大扫描范围 | 全库 | 1,000 |
| 任务耗时中位数 | 2,941ms | 2,528ms |
| 首任务开始到末任务结束 | 65.57 秒 | 61.07 秒 |
| 同根任务重叠 | 无 | 无 |
| 最后一批 1,000 个版本 | 全部正确 | 全部正确 |

累计扫描减少约 88%。持续写入持续时间由测试输入节奏决定，不能把上述总时间差解释为相同固定工作量的吞吐提升。合并中间版本符合索引最终状态的目标，没有要求逐个保存历史版本。

基线测试在此阶段包含一个额外验证文档，共 10,001 个；本轮删除后为 10,000 个。这个输入差异需要保留在解释中。

精确扫描的早期复测曾发现 142 个文件未更新。检查发现旧监听过滤忽略了重扫标记，逐事件读取配置并合并大队列也会阻塞通知消费。补上重扫处理、改为快速收集后，重新测试千文件突发和持续写入，最终内容全部通过。没有单独隔离两项修复各自的贡献。

## 遍历形态复测

每种形态仍为 10,000 个文件；首次 `index-only` 后再运行五次无变化任务。表中为完整无变化任务的中位耗时：

| 形态 | 基线 | 本轮 |
| --- | ---: | ---: |
| 平铺根目录 | 314ms | 224ms |
| 100 个子目录 | 327ms | 227ms |
| 1,000 个子目录 | 347ms | 250ms |
| 32 层公共路径再分目录 | 721ms | 542ms |

每轮均验证扫描数为 10,000、后五次索引数为 0。深路径仍会增加字符串和状态处理成本，本轮没有将其与文件系统遍历成本单独拆分。

## 独立 CLI 与读取器

使用最终构建运行：

```bash
pnpm benchmark:index --files 10000 --dirs 100 --unchanged-runs 3
```

- 首次完整索引：7,690ms；基线同脚本为 7,581ms，首次导出成本没有明显改善。
- 无变化刷新：478 / 270 / 271ms，中位数 271ms；三次快照和导出重写均为 0。
- 单文件追加：586ms；词项改变：717ms。

真实离线导出读取器验证了 `duringrununique` 命中 1 个、`bulkuniqueword` 命中 999 个、`finalversion29` 命中 1,000 个，已替换的 `finalversion0` 命中 0 个。首次离线查询约 124ms，后续不同查询约 3–18ms；分片会增加需要读取的文件数，不能只描述写入收益而忽略读取开销。

缓存目录读取 20 次的中位耗时约 1.11ms，范围 1.03–3.04ms。桌面原生查询与离线搜索使用不同读取路径，分别验证。

## 最终验证与限制

- Rust：43 项测试通过，debug 构建通过且无未使用代码警告。
- 服务端：37 项测试通过。
- 前端：2 项原生同步测试、10 项索引迁移测试、8 项标签树测试通过。并行文件测试曾被 SIGTERM 中断；最终逐文件单 worker 重跑全部通过。
- indexer、server 和 web 构建通过；web 仍有原有的包体积和混合导入提示。
- `git diff --check` 和基准脚本语法检查通过。

没有测试发布构建、Windows、网络磁盘、大型 PDF/Office 或多资料库缓存驻留内存。缓存会保留最新状态，本轮没有完整采样桌面进程树的峰值内存，因此不作内存下降的结论。测试程序、前端服务和临时资料库在验证后清理，没有修改用户原有资料库，也没有创建 Git 提交。

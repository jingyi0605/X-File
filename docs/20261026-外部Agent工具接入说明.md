# X-File 外部 Agent 工具接入说明

日期：2026-10-26
更新：2026-10-27

X-File 通过同一个原生可执行文件提供 CLI 与 MCP stdio。两种入口共用 MCP 工具目录、JSON Schema、业务实现和结果格式，直接使用 Rust 文档引擎，不需要启动图形窗口或 Node 后端。设置页的能力清单从该工具目录读取。

## 1. 找到可执行文件

仓库内构建：

```bash
cargo build --locked --manifest-path apps/desktop/src-tauri/Cargo.toml
apps/desktop/src-tauri/target/debug/x-file-desktop cli --help
```

macOS 已安装应用中的入口：

```bash
"/Applications/X-File.app/Contents/MacOS/x-file-desktop" cli --help
```

Windows 使用安装目录中的 `x-file-desktop.exe`。新工具随后续构建的可执行文件一起分发，已有旧安装包不会因为仓库更新自动获得这些入口；本轮没有创建或发布安装包。

不带子命令时仍启动原有桌面应用，`library-worker` 的现有索引调用方式保持不变。

## 2. CLI

先在桌面端或 Web 端「设置 → 集成服务 → 外部 Agent 接入」生成或设置 API Key，再打开接入开关。默认关闭，未配置密钥不能启用。生成密钥只有本次返回，应用仅保存摘要；换钥会使旧密钥失效，撤销会同时关闭接入。

将密钥通过环境变量交给 CLI 或 MCP 子进程：

```bash
export X_FILE_AGENT_API_KEY='<在设置中配置的密钥>'
```

Windows PowerShell 使用 `$env:X_FILE_AGENT_API_KEY = '<在设置中配置的密钥>'`。避免把实际密钥放入命令行参数、资料文件或对话；优先使用客户端密钥管理。`cli list/schema/skill/help` 是公开说明，无需密钥。

已有 MCP 的后续工具调用也读取最新开关与摘要；关闭接入不会强行中断已开始的操作。换钥后更新客户端环境并重新启动子进程。配置缺失、关闭或撤销返回 `AGENT_DISABLED`，密钥错误返回 `UNAUTHORIZED`，配置损坏返回 `SETTINGS_ERROR`。

设置页会依据资料库主机的程序、数据目录和平台生成配置及安装命令。Web 本地模式管理当前服务主机，镜像模式管理已配置的远端 API 主机；桌面本地模式继续调用原生命令。CLI/MCP 和安装命令必须在资料库主机运行，浏览器所在电脑不会因此获得远端主机的可执行文件。旧版主机缺少管理接口时，页面提示升级并支持重试。

### Web 与远端管理

管理接口为 `GET /api/integration/agent/settings` 和 `PUT /api/integration/agent/settings`，在 `full` 和 `sidecar-only` 两种服务模式中均可用。HTTP 服务通过 `library-worker agent-settings` 调用原生程序，继续共用桌面端的配置锁、摘要和原子写入；密钥不进入子进程命令行参数。主机需更新原生可执行文件；独立部署服务时可通过 `X_FILE_DESKTOP_CLI_PATH` 指定它，`X_FILE_DATA_DIR` 选择与桌面端、CLI 相同的应用状态目录。没有原生程序或程序过旧时返回 503，不另建一份配置。

Web 与桌面镜像模式都直接复用 HTTP 服务现有局域网用户名/密码登录。登录后浏览器携带同一个 HttpOnly 会话 Cookie 调用设置 API；未认证、会话失效或登出后，读取与修改都会被既有全局认证钩子拒绝。本机回环模式仍沿用现有本地访问策略。无需另配 Agent 管理令牌；Agent API Key 仍仅用于 CLI/MCP 工具鉴权，不用于 Web 登录。

同源部署不需要额外跨域配置。HTTP 服务只允许既有的本地开发来源和 Tauri 本地来源携带凭据；正式 Web 推荐与 API 同源部署。远端 HTTP 服务使用 HTTPS，并在主机已有网络服务设置中启用局域网访问认证、配置用户名和密码。设置 API 继承相同登录 Cookie 与登出失效行为；不再维护独立来源白名单或独立管理凭据。

此接口仅远端管理开关与密钥，不提供远程 MCP HTTP。异地主机上的 Agent 如需调用当前 stdio/CLI，需通过已有的 SSH 或进程代理在资料库主机启动工具。

此控制属于同一用户的本机工具接入约定，不隔离操作系统账户；持有有效密钥且未启用只读限制的客户端可调用目录中所有写工具。

```bash
apps/desktop/src-tauri/target/debug/x-file-desktop cli list
apps/desktop/src-tauri/target/debug/x-file-desktop cli schema xfile_file_operation
apps/desktop/src-tauri/target/debug/x-file-desktop cli call xfile_status
apps/desktop/src-tauri/target/debug/x-file-desktop cli call xfile_documents_list '{"keyword":"合同","limit":20}'
apps/desktop/src-tauri/target/debug/x-file-desktop cli call xfile_file_read '{"path":"docs/说明.md"}'
```

`list` 和 `schema` 返回 JSON，包含输入/输出 Schema、只读与破坏性标记，以及是否需要资料库绑定的元信息。Schema 是调用契约的唯一来源。

多行内容或需要规避 shell 转义时：

```bash
apps/desktop/src-tauri/target/debug/x-file-desktop cli call xfile_file_operation --input-file /absolute/path/request.json
```

也可通过 `--stdin` 读取标准输入中的 JSON。输入上限为 2 MiB。

使用独立状态目录：

```bash
apps/desktop/src-tauri/target/debug/x-file-desktop cli --data-dir /absolute/path/x-file-state call xfile_status
```

`--data-dir` 必须为绝对路径；未指定时沿用 `X_FILE_DATA_DIR`，再回退到用户默认状态目录。该目录保存应用绑定和设置，不是资料库根目录。资料库根目录只能通过明确的 `xfile_binding_set` 调用选择，路径必须已经存在。

只读模式：

```bash
apps/desktop/src-tauri/target/debug/x-file-desktop cli --read-only list
```

只读模式从发现结果中移除写工具，并在实际调用时拒绝这些工具。默认模式按当前用户文件权限执行显式请求的业务操作，不引入交互式审批面板。

调用结果：

```json
{"schemaVersion":1,"ok":true,"tool":"xfile_status","result":{}}
```

失败结果：

```json
{"schemaVersion":1,"ok":false,"tool":"xfile_file_read","error":{"code":"NOT_FOUND","message":"文件不存在"}}
```

退出码：成功为 `0`，业务失败为 `1`，参数错误为 `2`。stdout 只输出命令结果，业务日志写 stderr。

## 3. MCP stdio

```bash
apps/desktop/src-tauri/target/debug/x-file-desktop mcp
```

外部 MCP 客户端负责以子进程方式启动此命令，并持有 stdin/stdout。无需监听端口，不启动 HTTP 开发服务。

采用 `mcpServers` 配置格式的客户端可使用：

```json
{
  "mcpServers": {
    "x-file": {
      "command": "/Applications/X-File.app/Contents/MacOS/x-file-desktop",
      "args": ["mcp", "--read-only"],
      "env": { "X_FILE_AGENT_API_KEY": "<在设置中配置的密钥>" }
    }
  }
}
```

独立状态目录或只读连接通过 `args` 传入：

```json
["mcp","--data-dir","/absolute/path/x-file-state","--read-only"]
```

协议由官方 Rust SDK `rmcp` 处理。本轮真实子进程测试覆盖 `2025-11-25` 协议初始化、`tools/list`、`tools/call`、`resources/list`、`resources/read`、错误恢复和正常退出。仅声明实际提供的 tools / resources 能力。

业务错误在工具结果中设置 `isError:true`，并保留与 CLI 一致的结构化信封；未知工具/方法等协议错误按 JSON-RPC 返回。

## 4. 能力矩阵

| 能力 | 工具 |
| --- | --- |
| 应用状态、绑定 | `xfile_status`、`xfile_binding_get`、`xfile_binding_set` |
| 索引配置、快照 | `xfile_config_get`、`xfile_config_set`、`xfile_snapshot` |
| 文档检索、目录浏览 | `xfile_documents_list`、`xfile_files_list`、`xfile_host_directories` |
| 文件预览、内容与操作 | `xfile_file_preview`、`xfile_file_read`、`xfile_file_operation` |
| 收藏 | `xfile_favorites_get`、`xfile_favorites_set` |
| 索引 | `xfile_index_refresh`、`xfile_index_status` |
| 标签定义与规则 | `xfile_tags_list`、`xfile_tags_get`、`xfile_tags_create`、`xfile_tags_update`、`xfile_tags_delete`、`xfile_tags_ensure` |
| 文档、目录标签关系 | `xfile_document_tags_get`、`xfile_document_tags_set`、`xfile_folder_tags_get`、`xfile_folder_tags_set` |
| 标签重算 | `xfile_tags_recompute`、`xfile_tags_recompute_status` |

默认文档检索使用 `browseMode:"tag"`，在整个资料库内匹配标题、摘要和路径；目录查询使用 `browseMode:"folder"` 和 `selectedFolderPath`。这不是文档正文的完整全文检索，必要时再读取命中文档。

智能标签规则支持实际原生实现中的文件名、摘要内容、扩展名、目录路径和修改时间条件；关系为 `and` / `or` / `not`。关系查询分别返回手工/目录来源、已索引标签、派生标签和推荐标签，不能把这些来源混为一谈。

## 5. 文件与写入边界

- 业务文件必须使用绑定资料库内的相对路径。拒绝绝对路径、上级目录、内部状态目录和符号链接逃逸；写操作不跟随符号链接。宿主目录选择工具是显式浏览本机目录的例外。
- 文本写入上限为 512 KiB，覆盖写入必须提供读取时的 SHA-256 `expectedVersion`。版本冲突应重新读取并合并修改。
- 创建、复制和移动不覆盖既有目标；非空目录删除必须指定 `recursive:true`。目录复制最多处理 10000 个目录项，失败时清理本次创建的副本。
- `file_read` 文件大小上限为 20 MiB，单块最多 256 KiB。默认 UTF-8，可用 Base64 读取二进制；通过 `nextOffset` 继续，跨块版本变化时重新读取。轻量预览上限为 512 KiB。
- 文件操作后同步刷新原生索引；已有标签时同时重算，保持智能标签与当前摘要一致。若 `indexUpdated:false`，文件修改已经发生，应检查 `indexError` 并单独重试刷新。
- 外部工具写入通过应用状态锁串行执行，索引使用既有根目录锁。两个 Agent 对同一旧版本的写入只有一个成功；这不构成对任意桌面编辑器的强制文件锁。配置、收藏和标签仍采用现有持久化格式，与 GUI 同时修改同一设置时没有新增整体事务保证。
- 标签集合和收藏集合的保存会替换完整集合，调用方应先读取再合并。

## 6. SKILL

可分发文件：`skills/x-file/SKILL.md`。按照外部 Agent 的技能安装规则安装该目录即可，项目不会主动修改个人 Agent 配置。

同一份说明已嵌入可执行文件。使用 `~/.agents/skills` 的客户端可执行以下安装命令（再次运行会更新同名文件）：

```bash
mkdir -p "$HOME/.agents/skills/x-file"
"/Applications/X-File.app/Contents/MacOS/x-file-desktop" cli skill > "$HOME/.agents/skills/x-file/SKILL.md"
```

其他客户端将目录调整为其技能目录，保留 `x-file/SKILL.md` 结构。Windows 的 PowerShell 命令由设置页按本机路径生成。安装后重载技能，要求 Agent 使用 `x-file` 并调用 `xfile_status` 验证。仅查看内嵌说明：

```bash
apps/desktop/src-tauri/target/debug/x-file-desktop cli skill
```

MCP resource URI 为：

```text
xfile://skills/x-file
```

SKILL 说明工具发现、资料库选择、分页检索、版本化写入、标签、收藏、索引和错误恢复。它不绑定特定模型供应商，也不恢复内置 AI 助手。

## 7. 验证与当前边界

```bash
cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml --lib
pnpm test:agent-tools
```

`test:agent-tools` 使用真实可执行文件、临时状态目录与临时资料库；包含 CLI 输入形式、完整业务流程、路径及符号链接边界、并发版本冲突、MCP 协议和只读限制。

本阶段提供本机 CLI 和 MCP stdio，以及复用 HTTP 局域网登录认证的 Web/远端设置管理；不包含远程 MCP HTTP 或其认证、模型对话、任意命令执行、应用重置或自动更新控制。Windows 安装包和第三方 Agent 的实际配置界面尚未实机验证。

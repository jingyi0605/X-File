# 设计文档：X-File 资料库备份与恢复

状态：完成

## 1. 架构

正式桌面路径使用 Rust Native Core。前端通过 Tauri 命令导出序列化 JSON，并通过 `<input type="file">` 读取备份内容后调用导入命令；不增加文件对话框插件或应用权限。受支持的 Node HTTP 服务路径提供同一备份契约，便于测试和非默认调试集成。

## 2. 备份契约

备份对象包含：

- `format`: 固定标识 `x-file-library-backup`。
- `version`: 当前格式版本 `1`。
- `createdAt`: ISO 时间。
- `library`: 根目录名称与按 POSIX 分隔符排序的相对目录路径集合，路径仅记录深度 1、2 的目录。
- `tags`: 标签定义、规则、文档手工绑定和文件夹绑定；导入时改写 `libraryId`、`rootDir` 为当前绑定。
- `favorites`: 当前资料库收藏。
- `index`: 可立即读取的 catalog snapshot 和必要的持久化索引状态快照；运行任务、worker 身份和旧绝对路径不进入备份。

索引快照是便于恢复后的快速显示缓存，不是文档真源。导入完成立即安排全量索引刷新，由既有 Native/Indexer 主链校正文件变化、删除过期记录；随后复用标签任务中心按恢复的标签规则重建派生标签。

## 3. 结构匹配

指纹包括当前根目录 basename，以及根目录下相对深度为 1 或 2 的全部真实目录路径。忽略 `.ai-index` 和 `.x-file` 应用生成状态目录，不跟随符号链接；文件和目录内容不读取。名称及路径精确比较。比较前完整解析并校验备份 JSON，因此格式错误或结构不匹配均不会进入写入阶段。

## 4. 导入事务

1. 解析版本化备份并验证字段、tag 引用和相对目录路径合法性。
2. 读取当前 binding 并获取该根目录现有 scheduler 锁。
3. 计算当前浅层目录指纹并与备份比较；不匹配即释放锁并返回差异，不触碰存储。
4. 将标签和收藏归属映射至当前 binding，写入标签 store、favorites store 及索引快照。
5. 释放锁并安排全量索引刷新；索引任务完成后按恢复的标签规则重新生成标签结果。

失败语义需避免校验失败后的部分写入。提交多文件若发生 I/O 错误，尽量先写临时文件再替换；设计实现时复用现有原子 JSON 写入模式。

## 5. UI

在资料库设置增加备份模块，仅桌面本地模式显示。复用 `SettingsModule`、`.button-row`、`.primary-button`、`.secondary-button`、全局表单样式和双语 i18n。导入通过隐藏文件 input 选择 JSON；成功后显示恢复结果，失败显示错误。遵循前端开发规范，不新增局部颜色/尺寸。

## 6. 验证

- Rust：指纹深度、排除状态目录、结构不匹配不写入、格式版本拒绝、当前 binding remap、成功导入快照与标签。
- 服务端：Backup service 单测及 HTTP route 集成测试。
- Web：设置入口渲染、导出下载、选择导入、错误/成功状态和模式隐藏测试。
- 运行 server/web typecheck/build、聚焦测试与 Rust 测试；不启动 dev server。

## 7. 风险

- 快照文档可能包含已删除路径；导入后必须安排全量刷新，且状态提示不能声称刷新已完成。
- 本地目录结构扫描会遇到权限错误；应返回失败而不是生成不完整指纹。
- 原生和 HTTP 两条路径若各自维护不同 JSON 契约，可能产生不可互导的备份；使用共享 TS 类型/fixture，并让 Native 采用相同字段命名及版本。

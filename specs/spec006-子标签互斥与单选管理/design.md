# 设计文档：子标签互斥与单选管理

状态：Draft

## 1. 概述

### 1.1 目标

- 将互斥建模为父标签的直接子标签选择模式，复用现有标签树。
- 在赋值写入和有效标签合并两个边界落实单选语义。
- 保留来源数据，防止互斥策略变化造成静默数据丢失。

### 1.2 覆盖需求

- `requirements.md` 需求 1—5。

### 1.3 技术约束

- 桌面主执行路径：Rust Native Core `apps/desktop/src-tauri/src/native_core/tag_core.rs`。
- UI 与共享 DTO：`apps/web/src/features/library/LibraryPage.tsx`、`packages/shared/src/library-types.ts`、`apps/web/src/shared/library-types.ts`。
- 兼容服务端实现：`apps/server/src/library/tag-service.ts`、`apps/server/src/storage/tag-store.ts`。
- 重算、任务与导出复用现有标签任务中心，不新增任务体系。
- 前端遵循 `docs/20260609-前端开发规范.md`，继续使用现有 `DesktopModal`、`ModalAtoms`、表单与全局样式。

## 2. 架构

### 2.1 系统结构

`父标签设置 UI -> 标签定义保存 -> Native Core/服务端持久化 -> 文档/文件夹来源绑定与规则匹配 -> 单一有效标签解析器 -> 运行时 snapshot、浏览/搜索/计数/导出`。

手工编辑器负责即时替换体验；写入层负责守住数据不变量；统一解析器负责不同来源合并后的一致结果。任何只在 UI 中过滤兄弟标签的实现都不完整。

### 2.2 模块职责

| 模块 | 职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| 标签管理 UI | 编辑父标签多选/单选配置 | 标签详情、编辑值 | 标签定义保存请求 |
| 赋值编辑器 | 选中单选子标签时从当前选择中替换兄弟 | 当前选中 ID、新选 ID、父子关系 | 唯一的选择集合 |
| 标签写入服务 | 校验/归一化文档及文件夹绑定 | ID 列表、标签模式 | 有效持久化绑定或明确验证错误 |
| 有效标签解析器 | 合并来源并按单选组裁决 | 来源标签、来源层级、目录深度 | 无同组冲突的有效标签与裁决信息 |
| Native/HTTP 重算导出 | 更新 snapshot、索引和任务状态 | 标签存储、重算范围 | 一致的导出结果和任务状态 |

### 2.3 关键流程

#### 2.3.1 手工赋值

1. UI 根据标签 `parentId` 和父标签模式识别单选组。
2. 选择子标签 B 时，UI 从当前编辑集删除 B 的同父兄弟标签，再提交完整 ID 集合。
3. 后端重新验证单选约束；对旧客户端/直接 API 传入的冲突请求返回稳定业务错误，不使用数组次序隐式决定胜者。
4. 保存成功后沿用现有标签任务与增量导出流程。

#### 2.3.2 多来源有效标签解析

1. 对目标文件收集手工标签、有效文件夹绑定、智能规则匹配和系统派生标签，保留每条候选的来源元数据。
2. 多选父标签下的候选照常全部保留。
3. 单选父标签按 `parentId` 将直接子标签候选分组，每组最多保留一个。
4. 候选胜出规则按高到低：手工文档绑定 > 文件夹绑定 > 智能规则 > 系统派生。
5. 同源规则：文件夹绑定优先选择路径最具体的绑定；规则来源优先选择命中规则 priority 最小者；仍并列时按稳定 tag ID 字典序选择。手工/规则等仍并列的候选也以 tag ID 作最终稳定 tie-break。
6. 解析结果包含被隐藏候选的来源与胜出标签，供管理提示/详情诊断使用；不会删除底层来源绑定。
7. 仅最终有效标签进入 snapshot、搜索、计数及导出，标签详情 API 保留来源信息。

#### 2.3.3 开启或关闭单选

1. 保存父标签配置时，缺省保持未变；若配置由 `multiple` 切换到 `single`，标签定义先原子写入。
2. 使用现有后台重算机制更新有效 snapshot 和导出；源绑定不执行批量删除。
3. 关闭单选后重新计算时，仍然存在的所有来源标签恢复为有效标签。

## 3. 组件和接口

### 3.1 核心组件

覆盖需求：1—5。

- `ChildTagSelectionMode`：父标签的选择模式，取值 `multiple | single`。
- `resolveEffectiveTags`（名称以当前代码实现为准）：为单文件候选做统一分组裁决，结果可带 suppressed/conflict diagnostics。
- 手工赋值集合转换：同一用户交互中即时替换兄弟子标签。
- 标签详情/列表映射：读写新字段并保证旧存储默认值兼容。

### 3.2 数据结构

#### 3.2.1 标签定义

| 字段 | 类型 | 必填 | 说明 | 约束 |
| --- | --- | --- | --- | --- |
| `childTagSelectionMode` | `"multiple" | "single"` | 否 | 该标签直接子标签的选择模式 | 缺失/非法值按 `multiple`；仅影响直接子标签 |

现有文档和文件夹绑定仍保存原始 tag ID 列表。规则仍绑定各自目标标签；不将互斥关系复制到每个子标签或每条规则中。

#### 3.2.2 候选来源与裁决结果

候选内部至少保留 `tagId`、`tagPath`、`parentId`、`sourceType`、`sourceRef`，并可选保留 folder specificity、matched rule priority。解析结果包含有效候选和被抑制候选及胜出原因；对外 DTO 扩展字段为可选，避免破坏现有调用者。

### 3.3 接口契约

#### 3.3.1 标签定义保存/详情

- 类型：现有 Native invoke / HTTP 标签定义读写。
- 输入：现有标签定义字段加可选 `childTagSelectionMode`。
- 输出：现有标签详情加 `childTagSelectionMode`。
- 校验：只接受 `multiple` 或 `single`；旧客户端未传时更新操作保持已有值，新建时默认为 `multiple`。
- 副作用：模式变化触发已有重算任务；不清理源绑定。

#### 3.3.2 文档/文件夹标签保存

- 类型：现有 Native invoke / HTTP save document/folder tags。
- 输入/输出：兼容现有 `tagIds` / `createTagPaths` 契约。
- 校验：同一父标签为 `single` 时，直接子标签集合至多一个；无效冲突返回明确业务错误码及标签组信息，不按 ID 数组顺序静默挑选。
- 文件夹绑定校验以该绑定请求的直接集合为界；跨目录继承冲突由有效标签解析器按目录 specificity 裁决。

## 4. 数据与状态模型

### 4.1 数据关系

- 单选配置归属父标签定义；子标签通过现有 `parentId` 关联。
- 手工绑定、文件夹绑定、规则均保持各自来源真源，不为实现互斥而互相改写。
- 有效标签是针对某个文件、按当前配置派生的结果，不是新的持久化真源。
- 只有 active 标签参加赋值及有效结果；禁用、删除和移动沿用现有语义，重新按当前 parentId 建立分组。

### 4.2 状态流转

| 状态 | 含义 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| `multiple` | 子标签可并存，兼容默认 | 新建/旧数据缺字段/用户选择多选 | 管理员切换为 `single` |
| `single` | 有效结果每个父标签组至多一个直接子标签 | 管理员开启单选 | 管理员切回 `multiple` |

配置切换后，后台重算状态沿用现有 `queued/running/failed/idle` 状态机；重算失败不回滚源绑定，也不得宣称结果已刷新。

## 5. 错误处理

### 5.1 错误类型

- `LIBRARY_TAG_EXCLUSIVE_CHILD_CONFLICT`：写入集合包含同一单选组多个直接子标签。
- `LIBRARY_TAG_NOT_FOUND`：赋值或配置引用不存在标签。
- 现有标签重算/导出任务失败：使用现有任务错误语义。

### 5.2 处理策略

1. UI 选择时先替换兄弟标签，正常交互不触发冲突错误。
2. API 冲突时返回可识别业务错误，不静默按数组顺序覆盖。
3. 跨来源冲突不是写入错误；解析器按确定性优先级裁决，并保留诊断信息。
4. 配置保存后重算失败时保留配置与任务错误，可通过现有重算恢复入口重试。

## 6. 正确性属性

### 6.1 单选不变量

对于任意文件和任意启用单选的父标签 P，最终有效标签中满足 `parentId = P.id` 的直接子标签数量不超过 1。

**验证需求：** 需求 2、3。

### 6.2 来源保真

对于任意来源候选，开启或关闭单选只改变派生的有效结果，不删除或改写原始手工/文件夹/规则来源。

**验证需求：** 需求 4。

### 6.3 确定性

对于同一组标签定义、来源候选和规则优先级，解析器多次运行得到相同有效标签与冲突诊断。

**验证需求：** 需求 3、4、5。

### 6.4 向后兼容

对于缺少 `childTagSelectionMode` 的旧数据，读写与解析语义等价于旧版多选行为。

**验证需求：** 需求 1、5。

### 7.1 单元测试

- 默认多选、单选直接兄弟分组、不同父标签/不同深度不互斥。

- 来源优先级、最近目录优先、规则 priority、最终 ID tie-break。
- 被抑制诊断可还原来源，移除胜者后次级来源恢复。
- 旧 JSON 缺字段、无效枚举及父标签重命名/移动/删除。

## 8. 风险与待确认项

### 8.1 风险

- 当前 Native Core 与服务端历史实现存在并行代码，漏改其一会造成运行模式语义漂移。
- snapshot 中直接/派生标签字段的既有含义需在实施时核对；不能只改详情 DTO 而遗漏搜索/索引消费路径。
- 互斥解析若丢失来源元数据，将无法解释为何某个标签被隐藏。
- 修改父子关系可能改变互斥分组；必须以当前 `parentId` 真源重算，不能缓存旧组 ID。

### 8.2 待确认项

- 默认裁决建议为手工文档 > 文件夹绑定 > 智能规则 > 系统派生；同级按目录 specificity、规则 priority、稳定 tag ID 顺序。实施前需以当前 snapshot 语义和产品预期复核。
- 初版只隐藏低优先级候选并提供诊断，不做“整理并删除冲突绑定”的批量迁移操作。
- 若冲突诊断进入公开 API，应确认其 DTO 的最小字段，避免扩大首版兼容面。

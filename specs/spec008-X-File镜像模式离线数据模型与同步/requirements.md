# 需求文档 - X-File 镜像模式离线数据模型与同步

状态：Draft

## 简介

当前 mirror 模式只是把 API 请求转发到另一台 X-File 主机。镜像端没有独立的数据模型，主端服务停止后无法查看资料库、标签或已有筛选结果，标签修改也无法在离线期间保留。

本 Spec 把 X-File 建模为一个主端和多个镜像端组成的数据模型。主端保存配置和文件索引真源，镜像端保存最近一次完整同步快照；镜像端只读文件模型和标签，标签修改以带时间戳的操作记录排队，恢复连接后提交主端并按最后修改时间合并。

## 术语表

- **System**：X-File
- **主端（Primary）**：持有资料库根目录、索引和配置真源的 X-File 实例。
- **镜像端（Mirror）**：同步主端数据模型并提供离线浏览的 X-File 实例。
- **镜像快照（Mirror Snapshot）**：主端一次性导出的配置、文件索引、标签和收藏数据。
- **待同步操作（Pending Mutation）**：镜像端离线产生、等待主端接收的标签定义或标签绑定修改。

## 范围说明

### In Scope

- 主端提供完整镜像快照接口。
- 镜像端持久化快照，断开主端后继续浏览文件模型、标签和筛选结果。
- 镜像端标签定义、文件标签和目录标签操作在离线时进入本地队列。
- 主端恢复连接后自动同步队列，并按修改时间处理冲突。
- 运行状态和界面提示明确区分在线、离线缓存和待同步状态。

### Out of Scope

- 多镜像之间的实时点对点通信。
- 离线文件正文、二进制预览资源和文件内容写入的完整复制。
- 镜像端直接修改文件、索引或主端资料库配置。
- 云端账户体系和多用户权限模型。

## 需求

### 需求 1：主端导出完整资料库模型

**用户故事：** 作为镜像端用户，我希望主端能导出一个完整且可版本化的数据模型，以便镜像端脱离主端服务仍能使用。

#### 验收标准

1. WHEN 主端收到镜像同步请求 THEN System SHALL 返回库绑定、库配置、索引状态、文件文档模型、目录模型、标签定义、标签规则、文件标签绑定、目录标签绑定和收藏。
2. WHEN 镜像端收到新快照 THEN System SHALL 以主端返回的版本和时间戳持久化快照，并能在重启后读取。
3. WHEN 快照缺少可选旧版本字段 THEN System SHALL 继续按现有数据默认值读取，不破坏旧库。

### 需求 2：镜像端离线浏览

**用户故事：** 作为镜像端用户，我希望主端停止后仍能查看文件和筛选标签，以便继续查阅资料库。

#### 验收标准

1. WHEN 主端不可连接且镜像端存在快照 THEN System SHALL 使用快照返回资料库概览、文件列表、文档列表和标签树。
2. WHEN 镜像端按关键词、目录或标签筛选 THEN System SHALL 在本地快照模型上完成筛选，不发出必需的主端请求。
3. WHEN 镜像端没有任何快照 THEN System SHALL 明确提示尚未完成首次同步，并保留重试入口。

### 需求 3：标签操作权限与离线队列

**用户故事：** 作为镜像端用户，我希望可以管理标签，但所有写入最终都由主端执行，以便保持一个配置真源。

#### 验收标准

1. WHEN 镜像端在线执行标签写入 THEN System SHALL 向主端提交操作，镜像端不直接写入主端文件或索引。
2. WHEN 镜像端离线执行标签定义、文件标签或目录标签操作 THEN System SHALL 先更新本地待同步模型、保存待同步操作并显示警告。
3. WHEN 镜像端执行文件创建、删除、移动、复制、写入、刷新或库配置修改 THEN System SHALL 拒绝本地执行并提示必须连接主端。

### 需求 4：恢复连接后的同步与冲突

**用户故事：** 作为主端管理员，我希望多个镜像端的标签修改可以安全汇入主端，以便恢复连接后得到稳定结果。

#### 验收标准

1. WHEN 镜像端恢复连接 THEN System SHALL 先读取主端最新快照，再按操作记录顺序提交待同步标签修改。
2. WHEN 同一标签定义或绑定在主端和镜像端都有修改 THEN System SHALL 以较新的修改时间记录为最终值。
3. WHEN 待同步操作成功或被较新主端记录覆盖 THEN System SHALL 从队列移除，并保存同步结果和失败原因。

## 非功能需求

### 非功能需求 1：性能

1. WHEN 读取已缓存镜像数据 THEN System SHALL 不等待网络请求即可返回首屏模型。
2. WHEN 主端生成镜像快照 THEN System SHALL 复用已有索引导出数据，不重新扫描文件系统。

### 非功能需求 2：可靠性

1. WHEN 网络请求失败、主端关闭或会话过期 THEN System SHALL 保留最后一次有效快照和未完成队列。
2. WHEN 同步过程被中断 THEN System SHALL 通过幂等操作 ID 避免重复应用同一条修改。

### 非功能需求 3：可维护性

1. WHEN 增加新的镜像数据字段 THEN System SHALL 通过版本化快照类型扩展，不改变现有 API 响应的必填语义。
2. WHEN 排查同步问题 THEN System SHALL 能看到快照版本、最后同步时间、队列数量和最近失败原因。

## 成功定义

- 主端停止后，已有镜像端仍可打开资料库并按目录、标签和关键词浏览。
- 离线标签操作在镜像端重启后仍在队列中，主端恢复后可自动合并。
- 文件写入类操作不会在镜像端悄悄落地。
- 现有 local 模式和在线 mirror 模式行为保持兼容。

# 需求文档 - 外部 Agent 平台与远程 MCP

状态：实施中（核心需求已实现，最终验收受现有工作区错误阻塞）

## 简介

X-File 已经可以通过本机 CLI 和 MCP stdio 让外部 Agent 访问资料库，但当前接入仍有三个实际缺口：

1. 访问策略主要由客户端的 `--read-only` 参数表达，服务端缺少可持久化的权限策略。
2. 组合搜索能力已经存在于部分 HTTP 和原生内部接口，却没有在所有 Agent 入口保持一致。
3. Agent 可以给单个文档或目录打标签，但无法用一次结构化调用处理任意搜索结果集。
4. 远程主机只能通过 SSH 或进程代理启动本机 MCP，缺少标准远程 MCP HTTP 接入。

本 Spec 把这些能力收口为一个外部 Agent 平台。外部 Agent 负责推理和交互，X-File 负责安全的资料库访问、检索、标签操作、任务状态和协议传输。

## 术语表

- **System**：X-File。
- **Agent**：通过 CLI、MCP stdio 或远程 MCP HTTP 调用 X-File 的外部 AI 工具。
- **Access Policy**：X-File 保存并强制执行的 Agent 访问模式和工具权限。
- **组合检索**：同时使用目录、标签、收藏、关键词、搜索范围和匹配模式进行筛选。
- **批量标签任务**：针对冻结后的文档集合执行加标签、移除标签或替换标签的操作。
- **远程 MCP HTTP**：通过现有 HTTP 服务承载 MCP Streamable HTTP 传输的远程接入方式。

## 范围说明

### In Scope

- Agent API Key 生命周期和访问策略。
- CLI、MCP stdio、远程 MCP HTTP 的统一工具契约。
- 多条件文档搜索。
- 批量文档标签操作和 dry-run。
- 批量任务状态、进度和错误返回。
- 远程 MCP HTTP 的鉴权、会话边界、请求大小和连接生命周期。
- 设置页、SKILL、文档和测试。

### Out of Scope

- 内置模型、聊天、会话和供应商插件。
- OAuth、企业 SSO、多租户权限和云端控制面。
- 向量搜索、嵌入和自动模型推理。
- 任意 Shell 或系统命令执行。
- 自动修改第三方 Agent 配置。

## 需求

### 需求 1：服务端强制的 Agent 访问策略

**用户故事：** 作为资料库所有者，我希望 X-File 自己强制执行 Agent 权限，以便客户端参数不能绕过我的安全设置。

#### 验收标准

1. WHEN Agent 接入被关闭或 API Key 无效 THEN CLI、MCP stdio 和远程 MCP HTTP 均拒绝业务工具调用。
2. WHEN access mode 为 `read_only` THEN 所有写工具都被隐藏或拒绝，客户端不能通过省略 `--read-only` 绕过。
3. WHEN access mode 为 `read_write` THEN 仍然执行工具自身的路径、版本、绑定、破坏性和 Schema 校验。
4. WHEN API Key 被轮换或撤销 THEN 后续远程 HTTP 请求和已有 MCP 会话的后续工具调用立即使用新策略校验。
5. WHEN 保存访问策略 THEN 设置文件不保存密钥明文，读取接口不返回密钥明文。

### 需求 2：统一 Agent 能力契约

**用户故事：** 作为 Agent 客户端，我希望不同传输方式提供完全一致的工具能力，以便不用为 CLI、stdio 和 HTTP 编写三套适配逻辑。

#### 验收标准

1. CLI、MCP stdio 和远程 MCP HTTP 共用同一份工具目录、输入 Schema、输出 Schema、错误码和业务实现。
2. MCP 工具结果保留结构化内容和 `isError`，CLI 保留结构化信封和非零退出码。
3. 新增批量标签、任务和组合搜索能力后，CLI `list/schema`、MCP `tools/list`、设置页能力目录和 SKILL 说明保持一致。
4. 所有远程 HTTP 协议错误、鉴权错误和业务错误都不回显 API Key 或其他敏感输入。

### 需求 3：多条件组合检索

**用户故事：** 作为 Agent，我希望用一个查询同时组合目录、标签、收藏和关键词，以便快速得到可操作的稳定候选集。

#### 验收标准

1. WHEN 查询包含多个标签 THEN 系统按 AND 语义匹配，并保留层级标签的子路径匹配。
2. WHEN 查询包含目录、收藏、关键词、搜索范围或匹配模式 THEN CLI、MCP、桌面本地模式和 HTTP 模式使用相同语义。
3. 搜索支持标题/文件名、路径和已索引摘要内容的明确匹配模式。
4. 搜索结果返回总数、分页信息、文档 ID、相对路径、标签、更新时间和索引状态。
5. 当索引尚未完成或结果快照不可用时，系统返回明确状态，不把“尚未索引”误报成“文件不存在”。
6. 搜索参数拒绝未知字段、非法路径、超过上限的标签条件和非法分页值。

### 需求 4：批量文档标签

**用户故事：** 作为 Agent，我希望一次给搜索结果集打标签，以便处理数百或数千个文件时不需要逐文件往返调用。

#### 验收标准

1. 批量标签支持按冻结的文档 ID 集合、目录范围或组合搜索条件选择目标。
2. 批量标签支持 `add`、`remove` 和 `replace` 三种操作。
3. `add` 和 `remove` 保留目标文件未涉及的手工标签；`replace` 只替换明确声明的手工标签集合。
4. 支持 `createTagPaths`，并在同一批操作中幂等创建层级标签。
5. 支持 dry-run，返回匹配数、预计变化数、跳过数和验证错误，不修改资料库。
6. 批量任务使用现有根目录锁和标签导出规则，不能修改范围外文档。
7. 重复提交同一批 idempotency key 不重复应用破坏性变更。

### 需求 5：任务状态和可恢复结果

**用户故事：** 作为 Agent，我希望知道批量操作是否完成以及哪些文件失败，以便可靠地继续处理。

#### 验收标准

1. 批量标签和全库重算返回稳定任务标识或明确的同步完成结果。
2. 任务状态至少包含 `queued`、`running`、`completed`、`failed`，并报告处理数量和阶段。
3. 任务失败时保留真实错误、已成功数量、失败数量和可定位的目标信息。
4. 任务状态查询不会因为另一个长任务占用 MCP 连接而永久阻塞。
5. 重试任务不会重新执行已经确认成功且具有相同幂等标识的变更。

### 需求 6：远程 MCP HTTP

**用户故事：** 作为运行在另一台机器上的 Agent，我希望通过标准 MCP HTTP 连接资料库主机，而不需要在客户端机器上安装 X-File 可执行文件。

#### 验收标准

1. X-File 在现有 HTTP 服务中提供远程 MCP HTTP 入口，不新增独立开发服务器或额外监听端口。
2. 远程传输使用 stateless Streamable HTTP，不创建或存储会话 ID。
3. `GET` 和 `DELETE /api/mcp` 返回明确的非支持响应；MCP notification 成功返回 202。
4. 远程请求使用 `Authorization: Bearer <Agent API Key>` 鉴权；禁止通过 URL 查询参数或普通业务 JSON 传递密钥。
5. HTTP MCP 与本机 MCP 使用相同的访问策略、绑定资料库、工具 Schema、结果结构和错误码。
6. 远程 MCP 默认拒绝跨来源浏览器调用，不把 MCP 端点变成公开浏览器 API。
7. 请求体、响应体、并发数和单次工具执行遵守现有输入大小、文件路径和任务限制。
8. 远程 HTTP 错误不泄露密钥、状态目录、宿主绝对路径或内部堆栈。
9. 文档明确说明 TLS、反向代理、网络暴露范围和 API Key 管理责任。

### 需求 7：接入设置和文档

**用户故事：** 作为资料库所有者，我希望在设置页看到准确的接入方式和权限状态，以便安全配置外部 Agent。

#### 验收标准

1. 设置页展示接入启停、API Key 状态、访问模式、远程 MCP 地址格式和工具能力。
2. 只读和读写示例与服务端真实策略保持一致。
3. 本机模式、镜像模式和远程 MCP HTTP 的主机要求有明确提示。
4. SKILL 和项目文档说明搜索、批量标签、任务状态、远程 HTTP 鉴权和错误恢复。
5. 不自动替用户修改第三方 Agent 配置。

## 非功能需求

### 非功能需求 1：性能

1. 组合检索不得因为暴露给 Agent 就触发文件系统全量读取；优先使用已有索引和导出快照。
2. 批量标签应以一次批量提交和一次范围导出为主要路径，避免每个文档单独触发一次标签导出。
3. 远程 HTTP 不得为每个工具调用创建新的长驻应用或 Node 服务进程。

### 非功能需求 2：可靠性

1. 远程请求断开后，已开始的文件修改结果必须通过任务状态或结构化结果可确认。
2. 文件和标签写入继续使用根目录锁、访问策略校验和版本冲突保护。
3. 旧版设置文件缺少新字段时，使用兼容默认值并通过下一次保存完成迁移。

### 非功能需求 3：可维护性

1. 远程 HTTP 和本机 MCP 不复制工具实现，必须调用同一个工具执行层。
2. 能力目录、Schema、输出契约和文档从单一来源维护。
3. 测试至少覆盖本机 stdio、CLI 和远程 HTTP 三种入口的关键一致性。

## 成功定义

- 外部 Agent 可以通过本机 MCP、CLI 或远程 MCP HTTP 完成状态查询、组合搜索、文件读取和批量标签。
- 远程 HTTP 和本机 MCP 对同一工具返回相同业务结构和错误码。
- 只读策略在服务端强制生效，API Key 轮换和撤销对已有连接的后续调用立即生效。
- 批量标签不再要求 Agent 对每个文档逐一往返调用。
- 关键 Rust、服务端、前端、CLI 和 MCP 端到端测试通过。

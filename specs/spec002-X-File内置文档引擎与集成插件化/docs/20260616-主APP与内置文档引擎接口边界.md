# 主 APP 与内置文档引擎接口边界

状态：Draft

## 目的

这份文档用于支撑 `spec002` 的任务 1.2。

它定义主 APP 与内置 `library-engine` sidecar 的边界，避免后续实现变成“把旧 Node 后端整体搬进另一个目录”。

## 总原则

`library-engine` 只做文档库引擎，不做主 APP 宿主，也不做 assistant。

主 APP 负责：

- 桌面窗口
- 设置和偏好
- 插件安装和注册
- provider / assistant 插件入口
- 文档库 API 对前端的兼容层
- `library-engine` 启停和健康检查

内置 `library-engine` 负责：

- 文件扫描
- 文档解析
- SQLite 初始化、迁移、读写
- 索引任务
- watcher
- dirty scope 解析
- export 快照生成
- 索引状态和进度

## Transport 选择

第一阶段建议采用本地 HTTP 作为过渡 transport。

理由：

- 当前前端和 server 已经围绕 HTTP API 运转。
- 可以最小化对前端文档库页面的改动。
- 便于本地调试、集成测试和健康检查。
- 后续如果要换成 stdio/RPC，可以由 `LibraryEngineClient` 屏蔽。

要求：

- transport 细节只能在 `LibraryEngineClient` 内部暴露。
- 前端不能直接知道 `library-engine` 的真实端口或协议。
- 主 APP 对前端继续提供稳定 API。

## 进程生命周期接口

### `startEngine()`

- 类型：主 APP 内部函数
- 责任：拉起内置 `library-engine`
- 输入：
  - `resourceDir`
  - `appDataDir`
  - `host`
  - `port`
- 输出：
  - `LibraryEngineHealth`
- 错误：
  - `ENGINE_START_FAILED`
  - `ENGINE_PORT_UNAVAILABLE`

### `stopEngine()`

- 类型：主 APP 内部函数
- 责任：停止内置 `library-engine`
- 输出：
  - 最新 `LibraryEngineHealth`

### `getEngineHealth()`

- 类型：主 APP 内部函数 / 本地引擎 HTTP
- 责任：读取内置引擎健康状态
- 输出：

```json
{
  "running": true,
  "version": "0.1.0",
  "startedAt": "2026-06-16T00:00:00.000Z",
  "lastError": null,
  "indexerReady": true,
  "sqliteReady": true,
  "watcherReady": true,
  "exportReady": true
}
```

## 文档库读接口

读接口不能触发重任务。

### `getSnapshot()`

- 类型：主 APP 调用 `library-engine`
- 责任：读取当前绑定、状态、标签、收藏、目录和文档总数
- 禁止：在接口内部启动全量扫描

### `listDocuments(input)`

- 类型：主 APP 调用 `library-engine`
- 责任：基于 export 快照和轻量补充信息返回文档列表
- 禁止：在接口内部同步刷新索引

### `listFiles(input)`

- 类型：主 APP 调用 `library-engine`
- 责任：列出真实目录文件
- 说明：这是轻量文件系统读取，不属于重索引任务

### `previewFile(input)`

- 类型：主 APP 调用 `library-engine`
- 责任：返回预览能力和预览内容
- 说明：读取单个文件可以同步，但必须有大小限制和路径越界保护

## 文档库重任务接口

重任务必须显式触发，不能藏在读接口里。

### `requestRefresh(input)`

- 输入：

```json
{
  "reason": "manual_refresh",
  "targetPath": null
}
```

- 输出：
  - `accepted`
  - `taskId`
  - `deduped`
  - `status`
- 责任：
  - 标记 dirty
  - 入队索引任务
  - 按 rootDir 去重

### `startWatcher(input)`

- 输入：

```json
{
  "rootDir": "/Users/example/Documents",
  "quietWindowMs": 750
}
```

- 责任：
  - 启动 watcher
  - 文件变化后只打 dirty 标记
  - quiet window 后合并刷新

### `stopWatcher(input)`

- 输入：

```json
{
  "rootDir": "/Users/example/Documents"
}
```

- 责任：
  - 停止指定 rootDir watcher

## 状态接口

### `getIndexStatus(rootDir)`

- 输出：
  - `fresh`
  - `stale`
  - `queued`
  - `running`
  - `queue_timeout`
  - `cooldown`
  - `failed`
- 要求：
  - 包含 `dirtyReasons`
  - 包含 `runningTaskId`
  - 包含 `runningStage`
  - 包含 `progress`
  - 包含最近错误摘要

## 错误模型

所有主 APP 到 `library-engine` 的错误必须归一为：

```json
{
  "detail": "文档库引擎不可用",
  "error_code": "ENGINE_HEALTH_FAILED",
  "field": null,
  "timestamp": "2026-06-16T00:00:00.000Z"
}
```

## 任务归属

### 主 APP 保留

- 插件管理
- assistant / CLI 插件入口
- HTTP API 兼容层
- 设置页
- Tauri updater
- 窗口和托盘
- OnlyOffice 外部配置 UI

### `library-engine` 负责

- `@x-file/indexer`
- SQLite catalog
- file scanner
- parser adapters
- `LibraryIndexService` 中真正执行索引的部分
- watcher 执行部分
- export builder
- search index builder
- tag recompute

### 暂不迁移

- assistant routes
- assistant session store
- assistant runtime service
- `@codingns/session-sync-core`
- Codex / Claude Code provider runtime

这些能力进入 Integration Plugin 后再接入。

## 验收口径

完成 `spec002` 阶段 2 后，需要满足：

1. 主 APP 无插件启动后，文档库主链路可用。
2. `library-engine` 健康状态可读。
3. `requestRefresh` 会进入引擎任务队列。
4. 读接口不会顺手启动索引。
5. assistant / CLI 不作为主 APP 正式依赖进入安装包。

# 当前打包与依赖边界清单

状态：Draft

## 目的

这份清单用于支撑 `spec002` 的任务 1.1。

它只回答三个问题：

- 现在安装包里到底带了什么。
- 哪些内容属于文档库核心能力。
- 哪些内容必须从正式安装包里移出，后续改成 Integration Plugin。

## 当前打包入口

当前正式桌面打包入口仍然是：

- `package.json` 的 `package:desktop`
- `scripts/package-desktop.sh`
- `apps/desktop/src-tauri/tauri.conf.json`
- `scripts/archive/20260616/prepare-bundled-server.mjs`

当前 `tauri.conf.json` 的 `beforeBuildCommand` 会执行：

```text
pnpm --filter @x-file/shared build
pnpm --filter @x-file/indexer build
pnpm --filter @x-file/web build
pnpm --filter @x-file/server build
node ../../scripts/archive/20260616/prepare-bundled-server.mjs
```

这意味着桌面包构建前会把 web、server、indexer 都构建出来，然后额外准备随包后端资源。

## 当前随包资源

`apps/desktop/src-tauri/tauri.conf.json` 当前仍声明：

```json
{
  "resources": {
    "resources/x-file-server": "x-file-server",
    "resources/x-file-runtime": "x-file-runtime"
  }
}
```

当前资源目录体积实测：

| 路径 | 体积 | 结论 |
| --- | ---: | --- |
| `apps/desktop/src-tauri/resources` | `336M` | 当前随包资源总量过大 |
| `apps/desktop/src-tauri/resources/x-file-server` | `226M` | 包含后端 dist、源码、node_modules 和 assistant 依赖 |
| `apps/desktop/src-tauri/resources/x-file-runtime` | `105M` | 独立 Node runtime，是主包体积大头之一 |

## 当前随包 Node runtime

`scripts/archive/20260616/prepare-bundled-server.mjs` 仍会：

- 安装 `node@22.16.0`
- 复制 Node 二进制到 `resources/x-file-runtime/node/bin/node`
- 让桌面壳优先用这个 Node 启动后端

`apps/desktop/src-tauri/src/lib.rs` 仍会从这些路径寻找随包 Node：

- `x-file-runtime/node/bin/node`
- `x-file-runtime/node_modules/node/bin/node`
- `x-file-runtime/package/node_modules/node/bin/node`
- `x-file-runtime/package/bin/node`

这条链路必须在 `spec002` 阶段 2 收缩。最终目标不是继续打包通用 Node 后端，而是让文档库核心能力由内置 `library-engine` sidecar 承担。

## 当前 server 依赖边界

`apps/server/package.json` 当前生产依赖：

| 依赖 | 当前用途 | 是否属于主包核心 |
| --- | --- | --- |
| `@x-file/indexer` | 文档库索引、SQLite、watcher、export | 是 |
| `@x-file/shared` | 前后端共享 DTO | 是 |
| `fastify` | 当前 HTTP API 宿主 | 过渡期保留 |
| `@codingns/session-sync-core` | assistant / codex / claude runtime 适配 | 否 |

`@codingns/session-sync-core` 必须从正式安装包链路中移出。

## 当前 assistant 进入主包的位置

当前 server 在 `apps/server/src/app.ts` 中直接注册 assistant：

- `registerAssistantRoutes`
- `AssistantController`
- `AssistantRuntimeService`

`AssistantRuntimeService` 当前直接依赖：

- `@codingns/session-sync-core`
- `ClaudeRuntimeAdapter`
- `CodexRuntimeAdapter`
- `ProviderRuntimeService`
- 本机 `claude` / `codex` 命令探测
- `~/.claude` / `~/.codex` 登录态

这部分不是文档库核心链路，不能继续进入正式安装包。

## 文档库核心内置范围

以下能力属于主 APP 内置范围，后续由内置 `library-engine` sidecar 承担：

- `indexer`
- `sqlite`
- `watcher`
- `export`
- 文件扫描
- 文档解析
- 标签推断
- 索引状态
- 导出快照
- refresh 调度
- dirty 标记和合并

这些能力不做成可卸载插件。

## 可选 Integration Plugin 范围

以下能力不进入主安装包，只能通过 Integration Plugin 接入：

- Codex assistant
- Claude Code assistant
- provider CLI 探测
- provider 登录态探测
- provider 会话桥接
- provider 权限请求映射
- assistant UI 入口

第一版 Integration Plugin 必须优先复用本机已安装 CLI 和登录态，不把 provider runtime 偷偷打回主包。

## 第一阶段硬边界

后续实现必须遵守：

1. 文档库无插件可用。
2. assistant / CLI 无主包依赖。
3. 插件安装目录必须在 APP bundle 外。
4. 插件模型只有 `Integration Plugin` 一层。
5. `@codingns/session-sync-core` 不得作为 `@x-file/server` 正式生产依赖进入主包。
6. `x-file-runtime` 和 `x-file-server` 这套通用 Node 随包资源只能作为过渡对象，不能作为 spec002 的目标形态。

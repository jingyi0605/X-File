# 需求文档 - 移除内置助手与外部 Agent 接入

状态：已完成（移除与本地 MCP／CLI／SKILL 接入均已验收）

## 简介与范围

X-File 不再承载模型运行时、对话、会话或权限审批。外部 Agent 负责推理与交互，X-File 负责文档库操作。

本轮范围：删除文档助手界面、状态、API、类型、助手专用插件与会话同步运行时，以及桌面打包资源；更新当前文档并验证保留能力。

原移除阶段不实现 MCP、CLI 或 SKILL。2026-10-26 用户要求继续在本 Spec 实施外部 Agent 接入，新增范围见需求 4–6。不删除用户历史数据，不重写历史 Spec。

## 需求 1：移除前端助手

**用户故事：** 作为用户，我希望文档库只显示文档管理功能，以便不再配置或启动内置 AI。

### 验收标准

1. 文档详情不再显示助手标签、创建会话或历史会话入口。
2. 前端不再包含助手组件、请求、翻译、样式与供应商图标。
3. 设置不再展示只服务于助手的 Codex、Claude Code 集成管理；ONLYOFFICE 保持可用。

## 需求 2：移除后端与桌面助手链路

**用户故事：** 作为维护者，我希望彻底删除助手运行链路，以便避免继续维护内置 Agent。

### 验收标准

1. HTTP 服务不再注册 `/api/assistant` 路由或初始化助手。
2. 删除会话存储、运行时、审批、附件接口、共享助手类型与专用会话同步包。
3. 删除仅服务于助手的插件运行时、插件管理入口及桌面原生供应商检测。
4. 正式包与准备脚本不再携带、复制或要求内置助手插件。
5. 不自动读取、迁移或删除历史助手数据。

## 需求 3：明确外部 Agent 接入方向并保护现有功能

**用户故事：** 作为外部 Agent 的使用者，我希望了解 X-File 的接入边界，以便后续通过稳定工具调用文档库。

### 验收标准

1. 当前说明明确未来以 MCP、CLI 与 SKILL 提供外部接入，并区分规划与已实现能力。
2. 保留文档管理、预览、标签、索引、镜像、网络设置、ONLYOFFICE 与更新能力。
3. 保留开始实施前已有未提交修改，不主动启动开发服务器。
4. 类型检查、前后端测试、前端构建和桌面相关检查有实际执行记录。

## 非功能需求与成功定义

- 不为删除功能增加替代状态、兼容运行时或空壳 API。
- 继续使用全局前端样式体系。
- 通过代码扫描确认活动源码没有残留助手运行链路，历史设计资料保留为历史记录。

## 需求 4：统一的原生文档库工具面

**用户故事：** 作为外部 Agent，我希望发现并调用与桌面文档库一致的能力，无需启动图形窗口或 Node 后端。

### 验收标准

1. CLI 和 MCP 共享一个工具目录、输入 JSON Schema、输出信封及错误码，支持参数校验和可选只读模式。
2. 覆盖状态、绑定、索引配置、快照、文档检索、目录浏览、文件预览和读取、文件创建/写入/复制/移动/删除、收藏、索引刷新与状态、标签定义/规则/关系/重算，以及 ONLYOFFICE 设置和状态。
3. 文件操作限定在绑定资料库内，阻止绝对路径、上级路径、保留目录及符号链接逃逸；覆盖写入必须提供内容版本，目标冲突不得覆盖。
4. 文件变更后刷新原生索引；同步刷新失败必须明确区分“文件已修改”和“索引未完成”，避免重复执行破坏性操作。
5. 多个外部 Agent 的变更串行执行，并复用原生索引根目录锁。明确与桌面应用并发时的版本及锁边界。

## 需求 5：可独立运行的 CLI 与标准 MCP

**用户故事：** 作为外部工具的使用者，我希望通过终端或 MCP 调用同一份原生实现。

### 验收标准

1. 现有桌面可执行文件增加 `cli` 和 `mcp` 入口，保留无参数 GUI 与 `library-worker` 原有行为。
2. CLI 提供帮助、工具列表、Schema 查询、工具调用、SKILL 输出，接受 JSON 参数、标准输入或输入文件。
3. MCP 使用官方 Rust SDK 和 stdio，支持协议初始化、工具发现/调用、SKILL 资源读取；stdout 不得混入业务日志。
4. 工具错误使用结构化结果，CLI 返回非零退出码，MCP 设置 `isError`；只读模式同时限制发现和调用。
5. 提供本地构建与安装包中的可执行路径示例，Agent 可以自行启动 stdio 子进程，不要求常驻开发服务。

## 需求 6：自包含 SKILL 与端到端验收

**用户故事：** 作为外部 Agent，我希望通过 SKILL 学会如何发现、读取和修改 X-File 资料。

### 验收标准

1. 仓库提供可分发 SKILL，说明运行路径、工具发现、资料库选择、检索、版本化写入、标签、索引状态和错误处理。
2. CLI 和 MCP resource 可以输出打包进可执行文件的 SKILL，不依赖仓库绝对路径。
3. 在临时资料库验证完整 CLI 流程，并通过真实 stdio 子进程验证 MCP 握手、发现、读写、错误、只读模式与退出。
4. 类型、构建与既有功能检查有实际结果；记录移除阶段已有测试失败，不将其误报为新回归。

## 需求 7：软件设置中的外部 Agent 接入管理

**用户故事：** 作为资料库所有者，我希望在软件设置中控制外部 Agent 接入、管理 API Key，并获取可直接使用的配置与 SKILL 安装说明。

### 验收标准

1. 「设置 → 集成服务」提供独立外部 Agent 卡片；默认关闭，未配置密钥不能启用。
2. 支持自定义、生成、换钥和撤销。生成的密钥仅本次返回；普通查询不回显明文，持久化只保留摘要。撤销同时关闭接入。
3. CLI 工具调用和 MCP 启动要求启用及有效 `X_FILE_AGENT_API_KEY`；后续工具调用重新校验，换钥使旧连接失效。CLI 目录、Schema、帮助和 SKILL 可公开读取。
4. 根据当前可执行文件、状态目录及操作系统生成 MCP 和 CLI 示例；默认只读，可切换读写示例；复制内容不自动嵌入真实密钥。
5. 展示 SKILL 导出安装命令、客户端目录调整及重载验证说明；不替用户修改个人 Agent 配置。
6. 镜像模式说明在资料库主机配置及运行工具；浏览器和旧版桌面端显示能力限制，不调用不存在的 HTTP 配置接口。
7. 不启动新的网络监听或开发服务器；接入控制不影响桌面内正常资料库操作。

## 需求 8：设置模块隔离与折叠

1. 外观、资料库、集成、网络和更新中的设置项使用边界清晰的独立模块，每个模块可单独折叠或展开。
2. 参考图示的标题栏、箭头、状态、独立开关及展开后的分隔线，继续使用现有主题和全局 token。
3. 最多一层折叠：外部 Agent 内部的 API Key、推荐配置和 SKILL 安装只使用标题与分隔线分组，更新说明同样不二次折叠。ONLYOFFICE 顶层卡片默认收起。
4. 折叠不丢失表单草稿、不提交设置；标题栏开关独立生效，反馈在折叠后仍可见。保留既有保存、ONLYOFFICE 弹窗和三次重置确认流程。

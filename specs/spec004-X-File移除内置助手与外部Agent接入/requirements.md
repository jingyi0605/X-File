# 需求文档 - 移除内置助手与外部 Agent 接入

状态：已完成（既有测试失败已在独立基线复现）

## 简介与范围

X-File 不再承载模型运行时、对话、会话或权限审批。外部 Agent 负责推理与交互，X-File 负责文档库操作。

本轮范围：删除文档助手界面、状态、API、类型、助手专用插件与会话同步运行时，以及桌面打包资源；更新当前文档并验证保留能力。

不在本轮范围：实现新的 MCP server、CLI 或 SKILL；删除用户磁盘上的历史会话、插件或文档；重写历史 Spec。

## 需求 1：移除前端助手

**用户故事：** 作为用户，我希望文档库只显示文档管理功能，以便不再配置或启动内置 AI。

### 验收标准

1. 文档详情不再显示助手标签、创建会话或历史会话入口。
2. 前端不再包含助手组件、请求、翻译、样式与供应商图标。
3. 设置不再展示只服务于助手的 Codex、Claude Code 集成管理；ONLYOFFICE 保持可用。

## 需求 2：移除后端与桌面助手链路

**用户故事：** 作为维护者，我希望彻底删除助手运行链路，以便避免继续维护内置 Agent。

### 验收标准

1. HTTP 服务不再注册 `/api/assistant` 路由或初始化助手。
2. 删除会话存储、运行时、审批、附件接口、共享助手类型与专用会话同步包。
3. 删除仅服务于助手的插件运行时、插件管理入口及桌面原生供应商检测。
4. 正式包与准备脚本不再携带、复制或要求内置助手插件。
5. 不自动读取、迁移或删除历史助手数据。

## 需求 3：明确外部 Agent 接入方向并保护现有功能

**用户故事：** 作为外部 Agent 的使用者，我希望了解 X-File 的接入边界，以便后续通过稳定工具调用文档库。

### 验收标准

1. 当前说明明确未来以 MCP、CLI 与 SKILL 提供外部接入，并区分规划与已实现能力。
2. 保留文档管理、预览、标签、索引、镜像、网络设置、ONLYOFFICE 与更新能力。
3. 保留开始实施前已有未提交修改，不主动启动开发服务器。
4. 类型检查、前后端测试、前端构建和桌面相关检查有实际执行记录。

## 非功能需求与成功定义

- 不为删除功能增加替代状态、兼容运行时或空壳 API。
- 继续使用全局前端样式体系。
- 通过代码扫描确认活动源码没有残留助手运行链路，历史设计资料保留为历史记录。

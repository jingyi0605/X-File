# 设计文档 - 移除内置助手与外部 Agent 接入

状态：已完成（移除与本地 MCP／CLI／SKILL 接入均已验收）

## 1. 目标与约束

覆盖需求 1、2、3。React 前端、Fastify 服务与 Tauri 桌面宿主只保留文档库及现有非助手集成。

用户已授权删除相关代码，并确认启动 spec004。实施前读取前端规范，保留工作区原有修改，不启动开发服务器。

## 2. 架构与数据所有权

### 2.1 当前关系

文档详情选择状态传入助手 hook，hook 调用 HTTP 助手接口；服务端通过插件清单加载会话同步运行时；桌面和 Node 同时维护供应商检测及插件注册表。仓库内两个集成插件均服务于内置助手，没有其他实际插件实现。

### 2.2 目标结构

文档详情只消费文档选择与预览状态。删除助手专用插件管理链路，ONLYOFFICE 独立保留。共享包仅导出文档库类型，服务端启动不再装配插件与助手。

未来的数据流为：外部 Agent → MCP / CLI → 文档库能力；SKILL 负责说明工具发现、参数、结果与错误处理。本轮仅记录方向，不新增未实现的接口承诺。

## 3. 组件和接口

### 3.1 前端

删除 `features/assistant`，文档详情移除助手分支、会话弹窗和上下文转换；设置移除助手插件卡片及请求。同步清理翻译、图标、助手专用 CSS 与测试桩，保留通用详情、模态框和预览样式。

### 3.2 后端与共享类型

删除助手目录、路由、专用插件模块和注册表，删除 `session-sync-core` 工作区包及服务端依赖。移除共享助手及插件类型导出和前端桥接。

原助手与专用插件 HTTP 地址返回正常的未注册路由响应；不提供兼容运行时。

### 3.3 桌面与打包

删除原生插件列表、开关、供应商命令与登录检测，以及仅为助手传递的插件目录环境变量。删除两个插件的源清单与打包副本。资源准备脚本仍负责清理旧 Node 资源，但不再部署插件；资源边界与验包检查同步更新。

## 4. 数据与兼容性

不更改文档库状态模型与用户文件。历史助手会话和插件注册表留在用户磁盘上，不再由软件加载。移除的助手及专用插件 API 属于本次明确要求的行为变化。

现有未提交修改涉及 README、文档页、翻译、原生索引和启动脚本；在当前内容上进行局部编辑，禁止覆盖。

## 5. 错误处理

移除的 API 沿用 Fastify 未注册路由处理。ONLYOFFICE、HTTP 服务状态与文档库沿用现有错误契约。

## 6. 正确性属性

1. 打开文档页或设置页不会触发助手、供应商、插件管理请求。
2. 启动服务无需会话同步包或助手清单。
3. 正式包资源不含内置 AI 插件，验包脚本不再要求这些资源。
4. 文档详情预览、ONLYOFFICE 和其他现有核心功能保持原有契约。

## 8. 风险

- 原生宿主内的命令检测或路径工具可能被非助手代码复用，删除前必须检查调用关系。
- CSS 混合规则可能同时服务预览，需要保留通用选择器。
- 完整安装包签名、跨平台发布和外部 Agent 工具实现不属于本轮验收。

## 9. 外部 Agent 接入（扩展阶段）

覆盖需求 4、5、6。本章节替代此前“外部工具留待后续”的范围约束；阶段 1–3 的实现与历史验收保持不变。

### 9.1 架构和运行入口

`外部 Agent → CLI / MCP stdio → 共享工具目录与校验 → 原生文档库函数 / 索引 worker`

- 在桌面 Rust crate 内增加 `agent_tools` 模块，通过已有可执行文件的 `cli` / `mcp` 子命令运行；不启动 Tauri 窗口或 Node 服务。
- MCP 使用官方 Rust SDK `rmcp`，由 SDK 负责 JSON-RPC、协议协商和 stdio framing；仅声明实际实现的 tools 与 resources 能力。
- `--data-dir` 或现有 `X_FILE_DATA_DIR` 选择应用状态目录。资料库通过显式绑定工具设置，工具参数不能临时覆盖应用状态目录。
- 默认按当前用户文件权限提供文档库读写；可选 `--read-only` 从目录隐藏写工具，并在调用入口再次拒绝写操作。
- 本阶段实现本地 stdio 与原生 CLI，不引入远程 MCP HTTP 服务、认证、代理模型、任意命令执行、更新/重置应用等宿主控制能力。镜像 UI 及已有 HTTP API 保持不变。

### 9.2 单一工具契约

工具以 `xfile_` 为前缀，在一份内嵌目录中声明名称、中文说明、输入 Schema 和只读/破坏性标注。MCP 的 `tools/list`、CLI 的 `list` / `schema` 和实际调用共用该目录。

| 能力 | 工具组 | 底层来源 |
| --- | --- | --- |
| 状态、绑定、配置、快照 | status / binding / config / snapshot | 现有原生控制面与读取函数 |
| 检索、目录、预览 | documents / files / file_preview | 原生快照与文件读取 |
| 文本与二进制读取、文件操作 | file_read / file_operation | 有边界检查的文件系统操作 |
| 收藏 | favorites_get / favorites_set | 现有收藏存储格式 |
| 刷新与状态 | index_refresh / index_status | 原生 worker，刷新同步完成 |
| 标签定义、规则、关系、重算 | tags / document_tags / folder_tags | 现有 tag_core |
| 文档服务设置与状态 | onlyoffice | 现有原生设置，读取不返回密钥 |
| 宿主目录选择 | host_directories | 现有原生目录浏览 |

CLI 和 MCP 的结构化业务结果均为：

```json
{"schemaVersion":1,"ok":true,"tool":"xfile_status","result":{}}
```

错误为：

```json
{"schemaVersion":1,"ok":false,"tool":"xfile_file_read","error":{"code":"PATH_OUTSIDE_LIBRARY","message":"路径超出资料库","field":"path"}}
```

JSON Schema 拒绝未知字段，约束枚举、分页、文件读取和输入大小；错误码不依赖解析中文错误文本。原生模块尚未分类的错误通过稳定的 `LIBRARY_ERROR` 返回原文。

### 9.3 文件与状态一致性

- 路径先做跨平台相对路径检查，再校验真实路径属于已绑定的资料库。读操作禁止符号链接逃逸；写操作不跟随符号链接。
- `.ai-index`、`.x-file` 和资料库根目录不能作为用户文件修改目标；可见性按资料库配置处理。
- 文本覆盖必须匹配 SHA-256 `expectedVersion`；创建、复制和移动不覆盖既有目标。递归删除需要显式参数。
- 读取有长度上限，文本返回内容版本，二进制通过 Base64 分块读取。业务日志使用 stderr，避免破坏 JSON 或 MCP 流。
- 外部工具写入持有独立的应用状态锁，文件修改与索引分别使用现有根目录锁；避免嵌套获取同一索引锁。原生标签导出仍由 tag_core 获取根锁。
- 文件变更后同步刷新受影响路径，结果携带索引完成情况；若文件已修改但刷新失败，返回成功的文件操作结果与明确的 `indexUpdated:false` / `indexError`。
- 与桌面应用并发编辑时依靠内容版本发现冲突；配置、收藏和标签沿用现有存储格式，跨 UI 与 Agent 的整体事务不是本阶段新增保证。

### 9.4 SKILL 与分发

在 `skills/x-file/` 存放可分发 SKILL。用户要求的是项目提供给外部 Agent 的能力，因此文件留在项目中，不修改用户个人 Agent 安装目录。说明采用工具发现优先的流程，不复制一份易过期的全部 Schema。

SKILL 内嵌进 Rust 可执行文件；CLI `skill` 输出正文，MCP `resources/list` / `resources/read` 暴露固定 URI。使用说明展示构建产物和 macOS 应用包路径，工具不依赖当前工作目录。

### 9.5 验证与兼容

- Rust 单元测试验证路径边界、Schema、版本冲突和只读限制。
- 真实可执行文件在独立临时状态目录及资料库中运行，验证绑定、文件操作、检索、标签、收藏、刷新、预览、错误和跨进程版本冲突。
- 真实 MCP stdio 客户端完成初始化、发现、调用、resource、无日志污染及只读拒绝测试；异常请求不能导致后续合法请求不可用。
- 保持 `library-worker` 输出契约，复跑原生测试及服务端索引测试；前端没有新增 UI。
- 不宣称完成 Windows 实机安装、签名发布或远程 MCP 认证。

## 10. 外部 Agent 设置与本机鉴权

本节覆盖追加需求 7，并替代 §9 中“不引入认证”和“前端没有新增 UI”的阶段范围约束；仍不提供远程 MCP HTTP 或 OAuth。

- 数据由 Rust 原生模块管理，独立存放在当前状态目录的 `agent-integration.json`。字段为 enabled、apiKeyDigest 和 updatedAt；启用默认 false。GUI 通过两个 Tauri 命令读取和更新；外部工具目录不暴露密钥管理接口。
- 系统随机数生成 32 字节，编码为 `xf_` 前缀及十六进制字符；自定义密钥限定 32 至 512 位无空白 ASCII。只保存带固定域上下文的 HMAC-SHA256 摘要，通过常量时间校验函数验证。普通读取只返回开关、密钥配置状态、时间、平台及实际路径。
- 设置修改持有独立跨进程锁并原子替换配置；Unix 文件权限为 0600。客户端使用环境变量 `X_FILE_AGENT_API_KEY`，不增加明文命令行参数。该控制不隔离同一操作系统用户，也不赋予网络服务认证能力。
- MCP 启动先鉴权；共享业务入口每次读取最新配置并鉴权，写操作获得队列锁后再次检查。关闭、撤销和换钥影响后续调用，已开始的业务操作不强行中断。缺失设置视为关闭，损坏设置拒绝访问。
- CLI 的 list/schema/skill/help 是公开说明；MCP 连接建立后发现和 SKILL resource 同样仅返回公开说明。鉴权错误为 AGENT_DISABLED、UNAUTHORIZED 或 SETTINGS_ERROR，MCP 启动错误只写 stderr。
- 前端单独的 AgentIntegrationSettings 组件使用全局 token、统一按钮及既有 mac-switch 外观。示例选择只影响复制模板，不修改服务端权限；默认模板传 `--read-only`。密钥只在组件内短暂保存，普通模板始终使用占位符。
- 本地桌面模式使用原生命令；镜像模式提示到资料库主机配置，不远程修改本机设置；浏览器显示不支持。根据 macOS/Linux shell 或 Windows PowerShell 生成安装命令，SKILL 从已安装二进制导出。
- 验证覆盖原生设置生成、轮换、撤销、摘要和默认关闭；真实进程中的 CLI/MCP 失效校验；前端设置操作、模板、剪贴板失败及镜像模式；保留 ONLYOFFICE 回归。

## 11. 设置模块隔离

- 新增通用 `SettingsModule`，由原生按钮、`aria-expanded`、`aria-controls` 和受 `hidden` 控制的内容区域构成；保留挂载以维护草稿。最多只允许顶层模块一层折叠。
- 模块各自持有展开状态，标题栏的操作按钮与折叠按钮为兄弟节点；反馈显示在折叠内容之外。切换类别时使用类别 key 防止不同模块复用彼此的展开状态。
- 外观的语言/主题、资料库的绑定/索引、Agent、ONLYOFFICE、HTTP、更新和重置均消费同一模块；Agent 内部的三类内容以及更新说明使用普通标题与分隔线，不嵌套可折叠组件。
- 模块表面、间距、标题和说明字号由全局 token 管理，沿用当前主题与统一控件；窄屏标题栏可换行。
- ONLYOFFICE 默认收起，其他顶层模块默认展开；内部内容随所属模块显示，保留原有后端调用和敏感操作确认流程。

# Spec004 外部 Agent 接入验收记录

日期：2026-10-26

## 1. 范围与交付

助手移除阶段已提交为 `2a35eb1`（移除内置AI与文件助手及专用运行链路）。用户随后要求继续在 spec004 中实现外部接入，需求扩展至 4–6，完整技术方案见设计 §9。

本阶段交付：

- 31 项共享原生工具、一份输入目录、一份输出信封 Schema。
- 原生 `cli`：帮助、列表、单工具 Schema、JSON/标准输入/文件输入调用、SKILL 输出和只读模式。
- 官方 Rust SDK `rmcp` 的 MCP stdio：协议协商、工具发现/调用、资源发现/读取和结构化错误。
- 项目 SKILL、可执行文件内嵌副本及 `xfile://skills/x-file` resource。
- 文件路径与符号链接边界、版本化写入、外部写入状态锁、索引根锁和失败恢复。
- 通过公开标签入口重算，兼容并行 spec005 将标签根锁上移的改动；不覆盖任务中心实现。
- CLI / MCP 真实子进程测试及 macOS CI 检查。

接入手册：`docs/20261026-外部Agent工具接入说明.md`。

## 3. 端到端覆盖

测试均运行真实原生二进制，使用独立临时应用状态目录和资料库：

1. 工具发现与完整 Schema、三种输入形式、未知工具、参数错误、只读隐藏与调用拒绝、SKILL 内容一致性。
2. 绑定、配置部分更新、宿主目录浏览、创建与版本读取、UTF-8 分页、预览、文档检索、标签定义和规则、文档/目录关系、收藏、写入、复制、移动、删除、索引和 ONLYOFFICE 设置。
3. 绝对与上级路径、内部目录、符号链接逃逸、隐藏路径及系统目录别名、二进制 Base64、失败副本清理和 POSIX 复制权限保留。
4. 两个 CLI 进程用同一旧版本修改文件，验证一个成功、另一个得到 `VERSION_CONFLICT`，不丢失并发修改。
5. 人为把导出目录替换为文件，验证业务文件已经修改时仍返回 `success:true`、`indexUpdated:false` 和错误；恢复目录后单独刷新索引成功。
6. MCP `2025-11-25` 初始化、发现、读写与预览、错误恢复、未知方法/工具、resource、stdio 无日志污染及 EOF 正常退出。
7. MCP 只读进程隐藏写工具，且不能直接通过名称调用绕过。

## 4. 已知基线与边界

服务端仍存在移除阶段已经在独立已提交基线复现的两项失败：

- `library-index-e2e.test.ts` 的“摘要词项未变化时复用搜索桶和标签产物”。
- `onlyoffice-service.test.ts` 的“ONLYOFFICE 预览链接可以命中受控文件路由并返回真实文件流”，默认 `sidecar-only` profile 令绑定请求返回 503。

本阶段没有通过修改这些无关断言使测试变绿，也不将全量服务端测试描述为全部通过。

工作区并行任务中心及标签异步化变更已按用户确认保留；本阶段只对自身调用公开核心入口的方式做兼容调整。最终工作区差异中包括该并行开发内容，不能把所有未提交文件都归为本阶段。

本阶段不包含远程 MCP HTTP / 认证、模型对话、应用重置、任意命令执行、Windows 实机验收、第三方客户端实际配置界面验证或安装包发布。原生工具为同步业务调用，不新增跨 GUI 与 Agent 的全局事务保证。

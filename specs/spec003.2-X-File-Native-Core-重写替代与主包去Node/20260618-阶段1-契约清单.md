# spec003.2 阶段 1 契约清单

状态：进行中  
更新日期：2026-06-18

这份清单只做一件事：

**把 Native Core 重写期间绝对不允许漂移的 exports/runtime/bridge 契约钉死。**

## 1. 冻结范围

### 1.1 文件与目录契约

以下路径必须继续存在，且语义不变：

- `<rootDir>/.ai-index/runtime-status.json`
- `<rootDir>/.ai-index/runtime/active-file-state-snapshot.json`
- `<rootDir>/.ai-index/runtime/index-state.json`
- `<rootDir>/.ai-index/runtime/export-catalog-snapshot.json`
- `<rootDir>/.ai-index/exports/manifest.json`
- `<rootDir>/.ai-index/exports/status.json`
- `<rootDir>/.ai-index/exports/taxonomy.json`
- `<rootDir>/.ai-index/exports/bootstrap.json`
- `<rootDir>/.ai-index/exports/relations.json`
- `<rootDir>/.ai-index/exports/meta/*.json`
- `<rootDir>/.ai-index/exports/detail/*.json`
- `<rootDir>/.ai-index/exports/tags/*.json`
- `<rootDir>/.ai-index/exports/search/manifest.json`
- `<rootDir>/.ai-index/exports/search/*.json`

### 1.2 前端 bridge 契约

入口文件：

- `apps/web/src/runtime/native-library-bridge.ts`

冻结规则：

- 不改现有 exported function 名称
- 不改 Tauri command 名称
- `invokeOptional()` 失败时的“命令不存在 -> 返回 null”语义不变
- `getNativeLibraryTagRecomputeTaskOptional()` 必须继续返回 `{ available, value }`
- local/native 模式继续允许“桌面命令缺失时回退到 HTTP/空值”，不能把缺命令变成前端崩溃

### 1.3 server 读取契约

入口文件：

- `apps/server/src/storage/library-export-reader.ts`
- `apps/server/src/storage/library-runtime-status-store.ts`

冻结规则：

- `LibraryExportReader.readSnapshot()` 继续以 `exports/manifest.json` 为总入口
- `LibraryExportReader.listDocuments()` 继续通过 `meta_shards` 读取文档
- `LibraryRuntimeStatusStore.read()` 继续从 `runtime-status.json` 还原 `LibraryIndexStatus`
- `runtimeIndexState` 继续从 `runtime/index-state.json` 补齐失败/跳过/parser skip 信息

## 2. 字段 shape 契约

### 2.1 `runtime-status.json`

当前写入方：

- Node 路径：`apps/server/src/storage/library-runtime-status-store.ts`
- Rust 路径：`apps/desktop/src-tauri/src/native_index.rs`
- Rust 路径：`apps/desktop/src-tauri/src/native_export.rs`

冻结字段：

- `state`
- `lastRequestedAt`
- `lastStartedAt`
- `lastCompletedAt`
- `lastFailedAt`
- `nextAllowedAt`
- `runningStage`
- `errorSummary`
- `progress`

冻结语义：

- `state` 继续只表达运行状态，不塞入实现来源
- `progress` 可以为 `null`
- `dirtyReasons`、`workerHealth` 仍然不是磁盘持久化字段

### 2.2 `runtime/index-state.json`

冻结字段：

- `version`
- `generatedAt`
- `failedDocuments`
- `skippedDocuments`
- `parserSkips`

冻结语义：

- `failedDocuments[*]` / `skippedDocuments[*]` 继续保留 `path / extension / size / mtime / indexStatus`
- `parserSkips[*]` 继续保留 `skipKey / adapter / reasonCode / extension / samplePaths / sampleCount / totalCount / lastMessage / firstSeenAt / lastSeenAt / lastRunAt`

### 2.3 `runtime/export-catalog-snapshot.json`

冻结字段：

- `version`
- `generatedAt`
- `tags`
- `documents`

冻结语义：

- 这是 Rust Native Core 的中间真源，不是前端直接消费入口
- 但 export/search 必须继续以它作为 snapshot 主来源

### 2.4 `exports/manifest.json`

冻结字段：

- `version`
- `format`
- `generated_at`
- `entries.status`
- `entries.taxonomy`
- `entries.relations`
- `entries.bootstrap`
- `entries.search_manifest`
- `meta_shards`
- `detail_shards`
- `tag_shards`
- `relation_shards`
- `search_buckets`

冻结语义：

- `version=2`
- `format=static-v2`
- `entries.search_manifest` 继续指向 `search/manifest.json`
- `meta_shards[*].path`、`detail_shards[*].path` 仍然作为 reader 主导航字段

### 2.5 `exports/search/manifest.json`

冻结字段：

- `version`
- `format`
- `generated_at`
- `buckets`

冻结语义：

- bucket 文件仍按首字母/桶名分片
- 增量 search 允许只重建脏 bucket，但 manifest 合并结果必须仍可完整导航

## 3. 当前默认主链允许改什么

允许修改：

- Rust Native Core 内部模块划分
- desktop host glue
- adapter / executor registry / resource boundary
- 测试与契约文档

不允许修改：

- 前端样式 token
- 前端页面结构
- 现有 local/native bridge 返回 shape
- `exports/*` 与 `runtime*` 的现有读路径

## 5. 阶段 1 结论

当前可以明确的结论：

1. **真正必须兼容的是对外文件 shape、reader 入口、bridge 函数与命令名。**
2. **不必兼容的是旧 Node worker 内部层次、旧调度结构和旧 in-process 默认地位。**
3. **阶段 2 开始可以放心重写 Native Core，只要这些契约和测试不漂移。**

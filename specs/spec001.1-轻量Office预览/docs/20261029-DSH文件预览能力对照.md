# DSH 文件预览能力对照

## 结论

X-File 不需要整体复制 DSH 的页面和样式，但值得复制 DSH 在文件预览上的能力分层：

- 文件类型由独立 renderer 注册和分派。
- 文件读取、取消、超时和资源上限由共享生命周期管理。
- XLSX 使用真实只读网格，保留工作表、选区、复制和公式上下文。
- PDF 和图片提供连续阅读、缩放和统一工具栏。
- 不支持内容保留可读部分，并用紧凑提示说明缺失能力。
- 完整编辑交给系统应用，预览器不修改源文件。

## DSH 中已确认的能力

公开的 DSH 实现记录显示，浏览器 Excel 预览使用 FortuneSheet，并配合 ExcelJS、SheetJS CE 和 PapaParse 的包内适配层打开 XLSX、XLS、CSV 和 TSV。适配器接收字节、格式和限制，返回工作表数据，不直接持有 React 状态或组件引用。

DSH 的表格预览保持公式文本和文件中保存的计算结果，不在预览时重新计算；公式缺少保存结果时保持空白。它把图表、图片、形状和条件格式列为未支持内容，让可读单元格继续显示，并建议用系统应用打开完整文件。

DSH 还特别处理了几个容易被忽略的问题：

- 解析工作放入可取消的浏览器 Worker，并在解析前检查字节上限、矩形区域上限和超时。
- 工作表切换时保留有效初始选区，避免切换后出现空选区。
- 只读公式栏使用文本节点写入公式和单元格文本，避免把文件内容当作 HTML。
- 只读模式下保留冻结窗格计算，但隐藏拖动手柄。
- 复制行为对单元格文本、公式和保存结果进行 HTML 转义。

## X-File 现状与目标

| 能力 | 当前 X-File | 目标 |
| --- | --- | --- |
| 文本/代码 | 自研高亮、行号、复制、搜索和编辑 | 保留编辑能力，通过文本/代码 adapter 统一资源、状态和入口 |
| Markdown | React Markdown/GFM、代码块复制和搜索 | 保留渲染和编辑，由 Markdown adapter 接入共用 renderer 路由 |
| HTML | iframe/srcDoc、演示模式 | 保留现有路径，明确 sandbox、资源限制和本地回退 |
| 图片 | 图片标签和现有查看器 | 经 image adapter 统一缩放能力与状态 |
| PDF | PDF.js 连续页、懒加载、缩放和页码定位；当前可取消页面绘制，但已挂载 Canvas 不会在滚出活动窗口后卸载 | 增加活动页面资源回收和 detached 入口复用验证 |
| DOCX | docx-preview DOM 渲染，可选 LibreOffice 转 PDF | 优先可选 LibreOffice 转 PDF，失败回退轻量 renderer |
| PPTX | 浏览器 PPTX renderer，可选 LibreOffice 转 PDF | 优先可选 LibreOffice 转 PDF，失败回退轻量 renderer |
| XLS/XLSX | SheetJS + Worker + FortuneSheet 只读网格 | 保持网格、工作表、选区、复制和公式栏；不转 PDF；评估 ZIP 重复解压 |
| CSV/TSV | 文本 DTO 经分隔符解析后复用 FortuneSheet 网格 | 保持只读网格；纳入独立格式能力定义与适配器路由 |
| 不支持格式 | 部分类型仍会走普通文本分支 | 明确 unsupported，不把已知二进制误认为文本 |

## 不能直接照搬的部分

X-File 的资料库路径验证、20 MiB 资源限制、Tauri native bridge、桌面本地应用打开和现有全局样式都属于本项目边界，不能因为参考 DSH 而绕开。X-File 也必须保留文本、Markdown 和 HTML 的编辑路径。

LibreOffice 转 PDF 只用于 DOCX 和 PPTX 的可选高保真预览。XLSX 不走 PDF，因为 PDF 会丢失工作表导航、单元格选择以及公式与保存值之间的关系。

## 计划落地顺序

1. 维护单一格式能力契约，并独立表达索引、预览和编辑能力。
2. 用共享 resource controller 和按家族划分的 adapter registry 统一读取、解析生命周期。
3. 让主查看器、详情面板和 detached 入口复用同一 renderer 路由。
4. 保留格式语义：表格是只读网格，PDF 是连续页面，文本/Markdown 各自渲染；Office PDF 转换仅用于 DOCX/PPTX。
5. 验证跨端分类一致性、取消/释放、HTML sandbox、XLSX 解压开销及真实 WebView 行为。

# 设计文档：异步标签与统一任务中心

状态：完成

## 1. 问题证据

`native_save_folder_tags` 和 `native_save_document_tags` 是同步 Tauri 命令。其调用链在返回前执行 `sync_local_tag_exports_core`，等待文件锁、重建全库快照并导出索引。前端 `await` 不改变宿主命令的执行线程。现有界面只保存最后一个标签操作的本地状态，不能代表统一后台任务。

静态分析确认存在阻塞窗口事件处理的路径；并未通过性能录制断言 JavaScript 线程本身的耗时分布。

## 2. 后台执行与一致性

Tauri 标签命令改为异步命令，通过 `spawn_blocking` 执行现有同步核心，保留返回类型和错误语义。标签核心的公开写入口统一注册任务，并在读取标签存储前取得根目录锁，覆盖修改、快照和导出；避免导出阶段再次取得相同锁。

已有刷新调度器继续负责同根请求合并。每个提交注册任务，合并后统一更新关联任务。文件发现作为真实子任务注册；索引与标签计算按现有节流频率更新计数。

## 3. 任务模型与接口

共享 `LibraryTask`：`taskId`、`taskType`、`rootDir`、`targetPath`、`source`、`state`、`stage`、`totalCount`、`processedCount`、`errorSummary`、`queuedAt`、`startedAt`、`completedAt`。

可选 `categoryTitle` 保存此次分配的标签分类路径，多个分类以顿号连接。原生保存标签时在解析标签 ID 后写入当前任务上下文；HTTP 任务入队时记录相同信息。字段可选，兼容旧任务数据。

可选 `stageProgress` 保存当前保存阶段的真实计数，和标签计算的 `processedCount/totalCount` 相互独立。原生导出按文档详情、目录元数据、标签索引、关联、搜索及发布结果分阶段报告；已知文件数量才展示百分比，其余阶段使用无确定比例的进度提示。标签导出不再写索引 runtime-status，避免覆盖索引任务的时间线。

标签保存阶段使用标签计划中的目标文档路径作为 `changedPaths`，触发增量导出；详情和受影响目录元数据按本次范围报告阶段进度。任务中心右侧保留范围内的 `processedCount/totalCount`，左侧显示同一范围的当前保存阶段进度，避免出现两个不同口径的文件计数。

Rust 任务中心只持有小型运行记录，操作在锁外执行；线程上下文关联当前任务，嵌套遍历任务结束后恢复父任务。异常和 panic 均进入失败状态。每个文档库最多保留最近 5 条终态记录，按完成时间倒序清理；清理在状态更新及任务列表轮询时执行，活跃任务全部保留。

桌面读取接口：`native_list_library_tasks`，桌面事件 `x-file-library-task-updated` 传递任务快照；事件在任务锁释放后发送。HTTP 读取接口：`GET /api/library/tasks`，消费现有 TaskManager，保持远程入口可用。

## 4. 前端

独立任务中心组件在桌面端订阅任务事件，并定时读取列表兜底，避免整库快照参与高频轮询；用事件版本号避免请求期间到达的新事件被旧响应覆盖。显示活跃数量、任务类型、目标、状态、阶段和确定进度；总数未知时仅显示已处理数量。保留原索引统计与技术详情。任务状态以宿主为准，不再依赖标签弹窗内的假进度。

任务列表按 V3 HTML 的紧凑玻璃浮层展示：工具栏使用清单图标，任务行展示类型图标、状态标签、细进度条和带分组分隔符的计数；完成记录淡化显示时间。活跃任务不受条数限制，历史任务按完成时间倒序且最多显示最近 5 条；服务端和原生侧同步裁剪历史记录。任务行通过按钮展开目标、阶段和结果；最新索引任务展开后额外显示当前索引统计、目录状态与可进一步展开的技术详情。没有索引运行记录时，将只读索引状态按其真实完成时间纳入同一列表排序与条数限制，缺少时间时排在已知时间之后，不再固定置顶。索引统计采用双列网格，避免紧凑面板中的四列标签换行挤压。

浮层宽度 token 为 420px。共用数量预览组件覆盖活跃、终态和索引状态行，当前索引计数来自 `status.progress`，仅在稳态缺少进度时使用快照文档数量；总量未知时不虚构百分比。任务标题按 12px、分类名按 11px 统一 token 呈现，分类名使用主题灰色并保留完整路径提示。

标签分配开始时从运行时 catalog 冻结文档快照与范围索引，范围匹配后得到精确总数；后续处理与计数使用同一份计划，避免计数口径和实际工作集合漂移。CLI 通过 stderr 独立的带前缀 NDJSON 逐行报告统计、逐文件处理和导出阶段，Node 客户端增量解码并更新统一任务快照；stdout 保持兼容原有 JSON 结果协议。服务端标签范围任务不按库去重，并用同库 promise 链串行执行，以免丢弃不同范围或在工作进程读取标签数据前发生覆盖。

## 5. 正确性与验证

- 同目录写操作互斥，且等待锁不阻塞窗口事件线程。
- 任一阶段失败均成为终态，不残留永久运行状态。
- 合并请求、嵌套任务、历史裁剪、目录隔离有 Rust 单元测试。
- 前端验证三种任务、真实进度、失败、键盘操作和关闭后继续刷新。
- 执行前端类型检查、生产构建、相关前端与服务端测试、Rust 核心测试。

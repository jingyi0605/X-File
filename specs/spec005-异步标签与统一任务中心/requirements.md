# 需求文档：异步标签与统一任务中心

状态：完成

## 范围

修复桌面原生标签同步命令中的重计算；统一文档索引、文件遍历、标签分配的运行记录和状态展示。保留标签保存接口的返回结构、目录递归继承规则与既有索引技术详情。

## 需求 1：标签后台执行

用户故事：作为用户，我希望给大目录分配标签时仍能操作窗口。

1. 保存、读取和重新计算标签的原生命令不得在窗口事件线程执行全库计算或等待目录锁。
2. 标签修改必须在后台线程执行；原有调用者仍可等待保存结果。
3. 同目录的标签读改写与索引导出必须互斥，避免并发保存覆盖更新。
4. 所有失败阶段均须保留真实错误；不得提前报告成功。

## 需求 2：统一任务记录

用户故事：作为用户，我希望在同一个地方看到索引、遍历和标签分配。

1. 三种作业使用统一任务模型记录 ID、类型、目录、状态、阶段、计数、时间和错误。
2. 任务状态包含排队、运行、完成和失败；进度未知时不得虚构百分比。
3. 同根刷新合并不得丢失原有请求的任务记录和最终状态。
4. 活跃任务不得被历史裁剪移除；每个文档库最多保留 5 条历史任务，超出记录在轮询/任务状态更新时清理。
5. 历史任务按完成时间倒序排列；任务中心最多显示最新 5 条历史记录，活跃任务不受限制。

## 需求 3：任务中心

用户故事：作为用户，我希望通过原索引状态按钮打开任务中心。

1. 原入口改为任务中心，显示活跃任务数和统一列表，支持点击、键盘与原悬停行为。
2. 任务列表展示真实状态、阶段、进度与错误；关闭标签面板后仍可查看任务。
3. 保留索引统计、当前目录和可展开的技术详情。
4. 沿用全局样式与中英文翻译；切换文档库时不得显示旧库任务。
5. 任务中心按照 `data/x-file-dashboard-v3.html` 呈现紧凑任务行：类型图标、状态标签、细进度条与计数，完成记录显示时间并与活跃任务分隔。
6. 索引统计和技术详情默认收起，点击索引任务行后展开，再次点击收起。没有本次进程任务记录时，使用实际索引状态时间参与统一排序，不单独固定在首行；同样计入历史显示上限。
7. 浮层宽度使用 420px 并保留窄屏自适应；所有任务行默认展示数量预览，完成记录及当前索引状态行同样显示当前数量和总量。未知总量时仅展示已处理数量。
8. 标签分配任务标题旁显示真实标签分类路径，使用比标题小一号的灰字；长分类名省略显示，并提供完整文本提示。
9. 标签任务须先冻结本次真正参与计算的文档集合，再以该集合大小作为总数；目录任务不得沿用全库快照数量，单文档任务总数为 1。
10. 文件处理进度须由原生 worker 逐步异步上报；统计期间不显示虚构总数，全部处理后仍须显示保存阶段，只有导出成功后才能进入完成状态。
11. 同一文档库连续提交不同目录或文件范围时须分别登记并依次执行，不得按根目录去重而丢弃后续范围。
12. 标签文件计数与导出阶段进度分开记录。导出详情、元数据时展示真实阶段计数，未知总量的阶段显示处理中，不用计算满额伪装成全部完成。桌面端使用实时任务事件更新，轮询兜底且不能用旧响应覆盖新事件。
13. 标签导出不得修改文档库索引任务的完成时间或运行状态，避免历史排序被标签操作干扰。
14. 标签任务右侧数量只表示本次标签范围；保存阶段使用同一范围执行增量导出并显示该范围的阶段进度，不得回退到全库导出数量。

## 非功能需求

- 不启动开发服务器；使用单元测试、类型检查、生产构建和 Rust 测试验证。
- 保留已有未提交的外部 Agent 接入改动。
- 本次任务历史为进程内记录；不引入数据库、取消、重试或跨重启恢复的新协议。
